(`A2AOverlayDir`). `network_test.go` has one call site updated for the new
`sessionOwnsEndpoints` parameter, plus two hub cases.

- **`PeerGroupBackend` for Docker and Podman** (`*Backend`):
  - `StartHub` starts a stopped hub or returns the running one.
  - `StopHub` refuses while attachments remain.
  - `ReloadHub` sends SIGHUP.
  - `ConnectHub` checks that the address is free, connects, and on failure
    always disconnects and verifies with inspect (CR-P1P-3).
  - `DisconnectHub` verifies with inspect and falls back to `--force`.
  - `SignalWorker` runs `exec --interactive <worker> enclave-a2a-agent ctl`
    with the request JSON on stdin.
  - `ReloadGatewayOverlay` is `gateway.ReloadOverlay` on the session's
    gateway.
  - `ListHubs` lists by label.
- **Hub container:** created on the first member's bridge with `--network
  <bridge> --ip <addr>` (CR-A6-1).
  - Flags: `--cap-drop ALL` plus the six capabilities, `--read-only`,
    `no-new-privileges`, `net.ipv4.ip_forward=0`, `--tmpfs /run`,
    `--tmpfs /tmp`. No `--userns`, so rootless Podman uses its default
    mapping. No restart policy (A4).
  - Mounts: snapshots read-only, status and audit read-write. On SELinux
    they go through `--volume ...:z`.
  - Labels: the section 7 hub labels.
  - Env: group, group generation, `HUB_PORT=41820` (the snapshot's
    `hubPort`, A3), `PROXY_UID=65532`, the three directories, and
    `PeerGroupConfig.HubEnv` (log, retained results, reconnect window,
    `MAX_REQUEST_BYTES` from CR-A3-1). Caller env cannot override the
    fixed names.
  - Ready means both status files carry an epoch they did not carry before
    the start, with the right group generation, within 20 s.
- **Hub address:** the last usable IPv4 address of the inspected subnet:
  `.14` on a Docker `/28`, `.254` on a Podman `/24`. If another endpoint
  holds it, the next lower free address is used, and the chosen address is
  recorded. `--peer-group` is refused when the bridge has no IPv4 subnet or
  a prefix longer than `/29`.
- **Stale endpoint after a failed connect (Docker):** while the hub runs, a
  disconnect cannot remove the stale endpoint. `ConnectHub` therefore
  connects to a different free address on the same bridge, which
  overwrites the stale entry, and then disconnects. Other members are not
  disturbed. Before a stopped hub starts, `restartHub` disconnects
  endpoints whose network is gone or whose `NetworkID` is empty (P1-D
  finding 5, A6).
- **Ownership and teardown:** `sessionOwnsEndpoints(names, container,
  hubs)` treats an endpoint as owned when its name has the hub prefix and
  the container carries `enclave.a2a.hub=true` for that group.
  - `removeOwnedSessionNetwork` disconnects the hubs once only hubs remain
    and the session runtime is gone, then removes the network. It never
    uses `network rm -f`.
  - An unlabeled container named like a hub stays a foreign endpoint.
- **GC:** `gcPeerGroupHubs` runs at the start of `gcSessionNetworks` (every
  session start) and of `PruneStaleSessionNetworks` (`cleanup`, skipped on
  dry run).
  - It disconnects a hub from bridges that are gone, or whose session and
    gateway containers are gone.
  - It then removes hubs that have no attachment left.
  - It takes no group lock: a disconnect only cuts connectivity, and
    reconcile repairs the record.
- **Podman check:** `peerGroupMinPodmanIsolate = podmanIsolateOptedInOnly`
  is the single threshold. A network with isolate `true` or `strict`
  passes, and anything weaker is refused when the join reaches the session
  network.

## API for I1

```go
pg, err := dockerBackend.PeerGroups(ctx, backenddocker.PeerGroupConfig{HubImage, HubEnv, CommitTimeout, DepartureAckTimeout})
join, err := pg.Join(ctx, backenddocker.JoinSpec{...}) // takes the group lock, steps J1 to J5
req.PeerGroup = join.Session()                       // labels, env (tokens), overlay dir
be.Start(ctx, req) / be.Run(ctx, req, attach)        // steps J6 to J10, then the container; releases the lock
join.Abort(ctx)                                      // only if the caller fails before Start/Run
pg.Leave(ctx, backenddocker.LeaveSpec{Group, Member, Generation}) // background sessions, before removal
pg.Reconcile(ctx, group) / pg.ReconcileAll(ctx)
```

- `Start` holds the lock until the container exists. A failed container
  start rolls back the whole join.
- `Run` (foreground) releases the lock after commit. It leaves the group
  automatically when the session ends, before the gateway and bridge are
  removed. `join.LeaveResult()` reports that leave, so I1 can map
  `Degraded` to exit 3.
- `Start` or `Run` with a `PeerGroup` that `Join` did not prepare is an
  error. So is `--peer-group` with unrestricted networking.
- Defaults: commit timeout 5 s, departure ack timeout 30 s per worker.

## Join steps (proposal 15, under the group lock)

| # | Step | Undo |
| --- | --- | --- |
| J1 | Load the group record. When none exists, first remove a hub left by an earlier generation, then `GroupStore.Create`. Remove a hub whose generation label differs from the record. | `Delete(group, generation)` if this join created the record |
| J2 | Check that the name is unique, that there is at most one orchestrator, and run the worktree guard (warnings via `Join.Warnings`) | none (no side effect) |
| J3 | New member generation, then inventory `Add` (`admitting`) with `<config store>/a2a/<generation>` | `Inventory.Remove` |
| J4 | Issue tokens; a worker's outbound token goes into `host-secrets/outbound.json` | drop the outbound token |
| J5 | Record the member as `joining` (token hash, project path, mount mode, port, description) | remove the member, save |
| J6 | Once the session network exists: Podman isolation check, inspect the subnet, choose the hub address | none |
| J7 | Write the overlay (`active`, generation +1) before the gateway is created | remove the overlay directory |
| J8 | Once the gateway is ready, read its bridge address. Attach the hub: create it on this bridge, or restart a stopped hub (missing networks dropped, new-epoch wait) and `ConnectHub` | remove a hub this join created; otherwise `DisconnectHub` (failure adds an `engine-disconnect` obligation) |
| J9 | Publish N with the member, record `pendingRevision`, nudge the hub | publish a rollback revision without the member and wait. If that fails: `snapshot-commit` obligation; J8's undo still cuts connectivity |
| J10 | Wait for both acks of N, commit, `Prune(N, previous)` with `previous` read before the update (CR-A2-1) | none (J9's undo covers it) |
| J11 | Member `active`, inventory `member`, save | back to `joining` in memory; J5's undo removes it |
| J12 | Create the container (`Start`) or attach (`Run`), then release the lock | `Start`: a failure undoes J11 to J1 |

Undos run in reverse, keep going after a failed undo, and run detached from
cancellation, so an interrupted start still cleans up. A failed connect
never runs J8's undo, because `ConnectHub` cleans up its own failed attach.

## Leave steps (proposal 15, under the group lock)

Revocation is never undone. Only the leave intent has an undo, for a
failure before anything was revoked. Later failures degrade the result and
leave an obligation.

| # | Step | On failure |
| --- | --- | --- |
| L1 | Member `leaving`, `leaveIntentAt`, save | undo: restore the state and return the error |
| L2 | Publish without the member and wait for both acks. If the hub is not running, publish only: a restarted hub loads `current`, and reconcile commits it | degraded, `snapshot-commit` obligation; continue with L4 as the connectivity fallback |
| L3 | Orchestrator only: send `depart` (authoritative) to every active worker. A good ack is `confirmed` or `not-applicable` (CR-A8). Record the departure | unreachable worker: degraded, `departure-ack` obligation. `unconfirmed`: also a `quarantine-release` obligation |
| L4 | `DisconnectHub` from the member's bridge | degraded, `engine-disconnect` obligation |
| L5 | Overlay `active:false` (generation +1), wait for the cleared marker if the gateway runs, delete the directory | listed in `Problems`; the hub disconnect already cut connectivity |
| L6 | Remove the member and its outbound token; inventory `eligible`; save | listed in `Problems` |
| L7 | Last member: disconnect the hub everywhere, `StopHub`, `DeleteEligible` (store directory plus the transcripts in `contexts.json`, confined to the config store), `GroupStore.Delete` | an entry whose deletion fails keeps the inventory file; reconcile retries |

## Reconcile (`a2a_reconcile.go`)

Order, under the group lock. Reconcile waits at most 3 s for the lock and
otherwise reports the group `Busy`.

1. No record: remove the hub and delete the stores of every inventory
   generation.
2. Remove a hub of another group generation.
3. Expire host credentials.
4. Members:
   - `joining`: the join crashed; leave runs with inventory `eligible`.
   - `leaving`: finish the leave.
   - `active` whose container is gone or carries another member
     generation: leave, with an authoritative departure for an
     orchestrator.
   - An empty group is torn down.
5. Attachments: disconnect the hub from bridges no active member owns (this
   clears `engine-disconnect` obligations), and restart a stopped hub that
   still has members.
6. Republish when `pendingRevision` is set or a `snapshot-commit`
   obligation exists. An uncommitted revision is replaced, never committed
   late.
7. Retry `departure-ack`. Retry `quarantine-release`; release only when
   `descendantsAlive` is false.
8. Suspected departures: when the orchestrator runs with an unchanged
   generation, read each worker's `restrictions.json` from its config store
   and send `release-admission` for suspected stops on that principal.
9. Delete the stores of older inventory generations.

## Secrets ownership per engine

| Engine | Mechanism |
| --- | --- |
| Rootless Podman | `chmod 0400`, then `podman unshare chown 65532:65532 <staged secrets.json>`. Measured owner on the host: 165531 |
| Rootful Docker (host user) | A short-lived helper from the hub image: `run --rm --network none --user 0:0 --cap-drop ALL --cap-add CHOWN --security-opt no-new-privileges --read-only --log-driver none --entrypoint chown -v <staging dir>:/staging <hub image> 65532:65532 /staging/secrets.json`. Only the staging directory is mounted. About 0.23 s per publish. Measured owner: 65532 |
| Rootless Docker | Same helper. Container root is the host user, so 65532 maps into the subordinate range the hub sees (not measured, no rootless Docker here) |
| Host process is root | `peergroup.LocalSecretsOwner(65532)` |
| Docker with `userns-remap` | The same helper with `--userns=host`, chowning to the remap base plus 65532 (CR-A7-4, round 2). As root: local chown to that uid. Not measured on a remap daemon |

The helper is engine-side and uses the image the hub runs anyway. Nothing
on the host gains privileges. Its cost is one container run per published
revision (join, leave, credential).

## Change requests

All four are resolved in round 2 (see above); the round 1 text follows.

- **CR-A7-1** (section 8, `internal/backend/peergroup.go`): add a join hook
  to `PeerGroupSession`, for example a `Join` field with an interface that
  has `onSessionNetwork`, `onGateway`, `started` and `fail`.
  - Why: the join's engine steps must run inside session start, after the
    bridge exists, around the gateway and before the container. The current
    shape gives the backend no way to find the join.
  - Interim, inside my files: a package-level registry keyed by the
    `*PeerGroupSession` pointer that `Join` returns (`pendingJoins`).
    `prepareRun` looks it up. Accepting the CR replaces the registry with
    that field and changes nothing for I1.
- **CR-A7-2** (section 8, `HubSpec`): add the first attachment, for example
  `Initial *HubAttachment`, so that `StartHub` can create a hub.
  - Why: CR-A6-1 makes creation need a bridge and an address. Until then,
    `StartHub` on a missing hub returns `errHubNotCreated`, and only a join
    creates the hub (internal `createHub`). Reconcile and `stop` only need
    the start and stop paths.
- **CR-A7-3** (A6, `internal/docker`): the shared wrapper has no
  `--read-only` flag, no `--ip` on run, no stdin on exec and no
  `--env-file`. The hub run, the ctl exec and `podman unshare` therefore
  call the engine CLI directly (`engineCapture` in `a2a_engine.go`).
  - Proposed: add those primitives, then drop `engineCapture`.
  - Also: session env goes through `--env NAME=VALUE`, so the inbound and
    outbound tokens appear on the `docker run` argv for the lifetime of
    that CLI process, as every other session env value does today. An
    `--env-file` (0600 temp file) in `buildRunArgs` would close this. It
    is not A2A-specific, so it is not done here.
- **CR-A7-4** (P18, docs): `--peer-group` on Docker with `userns-remap` is
  refused for now.
  - Options: run the helper with `--userns=host` and chown to the remapped
    uid (needs the remap range); or have the helper create the file as
    65532 in a staging directory that is temporarily group-writable.
  - Enclave recommends `userns-remap` or rootless, so this should be
    settled before release.

Deviations without a CR:

- The hub address walks down when the last usable address is held.
- Leave publishes without waiting when the hub is not running.
- Reconcile reports `Busy` instead of blocking on a held lock.
