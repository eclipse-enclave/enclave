## Values and validation (`internal/config/a2a_options.go`)

- Values stay the configured strings in `model.A2AOptions` (embedded in
  `model.RunOptions`, so `RuntimeConfig.Run` carries them). Consumers parse
  with `config.ParseA2ADuration` (positive Go duration), `ParseA2ACount`
  (positive decimal) and `ParseA2ASize` (bytes, or a count with `KiB` or
  `MiB`). Env wiring (I1) must convert sizes to bytes:
  `ENCLAVE_A2A_MAX_*_BYTES` takes `ParseA2ASize`, not the raw option string.
- Flags validate on parse and name the flag in the error; `--role` and
  `--a2a-log` are case-insensitive and stored lowercase.
- Config files: invalid values are cleared with an `invalid_value` warning
  when the file is read (top level and per tool override), like
  `session_tint`, so the next layer or the built-in default applies.
- `config.ValidateA2AOptions(model.A2AOptions)` checks every value, rejects
  empty bounds, and rejects `a2a_host_send_wait` above
  `a2a_credential_lifetime - config.A2ACredentialSlack` (60 s, CR-P3-3). It is
  not called anywhere yet; I1 (run path) and A13 (`a2a send`) call it.
- `peer_group` is checked against a copy of `peergroup.GroupNamePattern`
  with a test that keeps them equal. Importing `internal/peergroup` from
  `internal/config` pulled `internal/a2a` into the gateway proxy build
  inputs (`TestGatewayProxyBuildInputsCoverInternalDeps` failed), the same
  coupling CR-A2-1 avoided.

## Decisions

- **Host send wait** (CR-P3-1) is a separate config option,
  `a2a_host_send_wait`, unaffected, no env. A13 owns any `--wait` flag on
  `enclave a2a send`; its value should override this option for one call.
- **Credential lifetime** (CR-P3-3): `a2a_credential_lifetime` is the 15 min
  cap; the per-invocation lifetime (bound + 60 s, 2 min for non-blocking
  verbs) is A13's computation.
- **Record max age** default is `168h`, because Go durations have no days.
- **Experimental marking**: the repo has no option-level experimental flag
  (qemu is marked in prose only), so the docs section is titled
  experimental and says so. The `--peer-group` usage string says
  "experimental".
- **`a2a_role` default `worker`** is a real default, so `config` shows it and
  `ps --json` provenance records `a2a_role: "worker"` (and every other
  affected `a2a_*` default) on every session, A2A or not, as for other
  defaulted options. I1 must use `Sources.A2ARole` (or any `a2a_*` source)
  being non-default to detect "`--role` without `--peer-group`".
- **`AffectsNetwork`** is not set on `peer_group`: the hub route is an
  overlay, not an allowlist entry, and `network print` does not model it.
