# F4 report: plain-session reconcile

Branch `a2a-f4`, based on `a2a` at `f383e00`.

## Rule (I1 decisions)

A session without `--peer-group` pays no A2A latency.

## Changes

- `command_run.go`: the plain-session `ReconcileAll` branch is gone. The
  run path calls `prepareA2ARun` (`a2a_wiring.go`), which returns nil for
  non-run actions and plain sessions; only a `--peer-group` run builds the
  lifecycle (hub image, `PeerGroups`, reconcile and join in the hook, as
  before).
- `command_stop.go`: `a2aStopLeaver` takes the containers to stop and uses
  `newA2AStopLeaver`, which reads the group records from disk and returns
  nil unless one of the containers is a member. No lifecycle, so no
  `docker info`, for a plain stop. After the stops, `reconcileLeftGroups`
  runs `Reconcile(group)` once per group a stopped member belonged to
  (sorted), instead of `ReconcileAll`. A degraded leave, a degraded
  reconcile or a reconcile error exits 3; a `Busy` group is logged as
  before.
- `a2a_wiring.go`: `a2aLeaver` records the groups of members that left;
  `newA2ALeaver` (cleanup, `stop --peer-group`) and `newA2AStopLeaver`
  share `a2aLeaverFor`. `reconcile` (`ReconcileAll`) is unchanged.

Unchanged: `--peer-group` runs, `stop --peer-group`, A2A verbs and
`cleanup --ephemeral` (all still `ReconcileAll`).

Consequence: a stale group whose members were removed outside enclave is
now repaired only by a `--peer-group` run, a member stop in that group,
`stop --peer-group`, `enclave a2a reconcile` or `cleanup --ephemeral`.
