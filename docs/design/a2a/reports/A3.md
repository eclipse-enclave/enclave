# A3 report: hub proxy (`cmd/enclave-a2a-hub`, `internal/a2ahub`)

Branch `a2a-a3`, based on `a2a` at `638be51` (fast-forwarded from
`6fdb667` for `a2a.EnvHubEpoch`). Owned files only; nothing outside
`cmd/enclave-a2a-hub/`, `internal/a2ahub/` and this report changed.

## Summary

`enclave-a2a-hub` has three subcommands:

- `proxy`: the unprivileged proxy. Reads `ENCLAVE_A2A_*` from the
  environment, refuses to run under a uid other than `ENCLAVE_A2A_PROXY_UID`
  when that is set, binds `0.0.0.0:<ENCLAVE_A2A_HUB_PORT>` (IPv4) with
  `TCP_USER_TIMEOUT` 10 s, registers SIGHUP, and only then loads `current`
  and writes `proxy.json`. Each SIGHUP reloads. SIGTERM or SIGINT closes
  every stream and exits 0.
- `render-rules [--snapshot-dir <dir>]`: the filter table for the supervisor
  (CR-A4-3 shape, example below).
- `call <path>`: host access over loopback.

The binary links only `internal/a2a`, `internal/a2ahub`,
`internal/peergroup`, `internal/model`, `internal/logx`, `internal/util`, the
standard library and `golang.org/x/sys/unix` (already a direct dependency;
used for `TCP_USER_TIMEOUT` behind a `linux` build tag). No `go.mod` change.
`go build` output is 10.5 MB unstripped.

### Errors

| Situation | Code | `ErrorInfo.reason` | HTTP on GET paths |
| --- | --- | --- | --- |
| No, unknown or malformed bearer token; no revision applied | -31004 | `UNAUTHENTICATED` | 401 |
| Token valid in an earlier revision of this epoch; expired host credential | -31003 | `REVOKED` (`member` = caller) | 403 |
| Target removed in an earlier revision of this epoch; stream cut by revocation | -31003 | `REVOKED` (`member` = target or caller) | 403 |
| Caller role not allowed on the path; target not a worker | -31005 | `ROLE_FORBIDDEN` | 403 |
| Target not in the revision, or not a valid member name | -31002 | `UNKNOWN_MEMBER` | 404 |
| Dial, read or mid-stream failure; adapter answered non-200 (`metadata.httpStatus`) | -31001 | `ADAPTER_UNREACHABLE` | 502 |
| Body above `ENCLAVE_A2A_MAX_REQUEST_BYTES` + 64 KiB envelope | -31018 | `REQUEST_TOO_LARGE` | n/a |
| Cached task of another principal | -32001 | none | n/a |
| Adapter response above 32 MiB, SSE event above 16 MiB, unparsable card | -32006 | none | 502 (card) |
| Invalid JSON-RPC body | -32700, -32600 (`a2a.DecodeRequest`) | none | n/a |

"Revoked" memory is bounded (4096 hashes, 4096 member names) and per epoch.

### Request order on `POST /peers/<name>`

Read body (bounded), decode JSON-RPC, authenticate and register for
revocation, `A2A-Version`, `A2A-Extensions`, role, target, owner cache,
forward. Refusals before authentication still carry the request `id`.

## `render-rules` example output

Snapshot of an orchestrator (gateway `172.18.0.2`, hub `172.18.0.14` on
`eth0`), `worker-1` (gateway `172.18.0.18`, hub `172.18.0.30` on `eth2`) and
`worker-2` whose hub address no interface holds yet:

```text
$ enclave-a2a-hub render-rules --snapshot-dir /run/enclave-a2a/snapshots
# enclave-a2a-hub group review revision 1
*filter
:INPUT DROP [0:0]
:FORWARD DROP [0:0]
:OUTPUT DROP [0:0]
-A INPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
-A INPUT -i eth0 -s 172.18.0.2/32 -d 172.18.0.14/32 -p tcp --dport 41820 -j ACCEPT
-A INPUT -i eth2 -s 172.18.0.18/32 -d 172.18.0.30/32 -p tcp --dport 41820 -j ACCEPT
-A OUTPUT -m conntrack --ctstate ESTABLISHED,RELATED -j ACCEPT
-A OUTPUT -o eth2 -s 172.18.0.30/32 -d 172.18.0.18/32 -p tcp --dport 41821 -j ACCEPT
COMMIT
```

stderr:

```text
warning: member worker-2: no interface holds 172.18.0.46; no rules rendered
revision=1
```

On refusal: exit 1, nothing on stdout, stderr is `revision=<n>` (when
`current` names one) followed by `render-rules: <reason>` as the last line
(CR-A4-3).

- Verification is `LoadCurrent` without parsing secrets (the hash is still
  checked) plus the same semantic checks as the proxy, minus outbound
  tokens. Group and group generation come from `ENCLAVE_A2A_GROUP` (checked
  when set) and `ENCLAVE_A2A_GROUP_GENERATION` (required). When
  `ENCLAVE_A2A_HUB_PORT` is set it must equal the snapshot's `hubPort`.
- The interface is resolved per member from `hubAddress` on every run
  (`net.Interfaces`), never cached. Names are checked against
  `[A-Za-z0-9._-]{1,15}` before rendering.
- Loopback accepts are omitted; the supervisor injects them (CR-A4-3, Q9).
  IPv4 only; the supervisor owns the fixed `ip6tables` DROP.
- A member whose hub address no interface holds gets no rules and a
  `warning:` line, and the revision still renders. That member is then
  cut off, and the supervisor's address diff treats its gateway as removed.
  This is fail-closed for that member and keeps a hub with a stale
  attachment serving the others. Refusing the whole revision would leave
  every member on the default deny after a hub restart.

## Change requests

- **CR-A3-1** (interfaces section 6, hub table; A7): the hub needs
  `ENCLAVE_A2A_MAX_REQUEST_BYTES` for -31018 ("hub, adapter" in section 11),
  but the hub table does not list it. The proxy reads it when set and
  defaults to 1 MiB, and allows 64 KiB of JSON-RPC envelope on top. Proposed:
  add it to the hub table; A7 sets it from `a2a_max_request_size`.
- **CR-A3-2** (interfaces section 11, errors; A11, A13): non-JSON-RPC hub paths
  (card, listing, control, liveness) have no specified error shape. The proxy
  answers them with an HTTP status (401, 403, 404, 502) and a JSON-RPC error
  body with `"id": null` and the same enclave code. This is the shape A11
  and A13 should parse. Proposed: record it in section 11.
- **CR-A3-3** (`internal/a2a/enclave.go`, A1): reasons for -31004, -31005 and
  -31018 have no constants. The proxy uses `UNAUTHENTICATED`,
  `ROLE_FORBIDDEN` and `REQUEST_TOO_LARGE`, defined privately in
  `internal/a2ahub/proxy.go`. Proposed: add `DeliveryUnauthenticated`,
  `DeliveryRoleForbidden` and `DeliveryRequestTooLarge` next to the existing
  three, so A10, A11 and A13 can share them.
- **Interpretations made without a CR** (please confirm):
  - -31003 also covers an expired host credential and a target removed
    earlier in this epoch. After a hub restart the memory is empty, and
    both cases become -31004 or -31002.
  - Version and extension headers are enforced on JSON-RPC POSTs only. Card,
    listing, control and liveness do not require them.
  - The control stream sends the current orchestrator state right after
    `hello`. If no orchestrator has connected since the hub started, the
    state is `connected: false` for the snapshot's orchestrator, with
    `since` set to the hub start. A10 can therefore start its reconnect
    window on hub start.
  - A card fetch failure is 502 with -31001. The hub does not synthesize a
    card from the snapshot, because queue depth is only known to the
    adapter.

## Coordinator items recorded

- **CR-A4-2**: the proxy adopts `ENCLAVE_A2A_HUB_EPOCH` (validated as 16
  lowercase hex). It is used in `proxy.json`, `hello`, audit and
  `X-Enclave-A2A-Epoch`. Without the variable it generates its own, for
  tests and standalone use. Tested by `TestProxyAdoptsSupervisorEpoch` and
  `TestProxyReloadsOnSIGHUP`.
- **CR-A4-3**: the output is one `*filter` table with all three DROP
  policies, INPUT `-s <gw>/32` and OUTPUT `-d <gw>/32` per member, and
  ESTABLISHED,RELATED accepts rendered. `lo` is omitted. `revision=<n>`
  goes to stderr on success and, before the reason, on refusal. The INPUT
  rules also carry `-d <hub>/32` and the OUTPUT rules `-s <hub>/32`. A4's
  awk diff reads only INPUT `-s` and OUTPUT `-d`, so this is compatible. The
  leading `#` comment line is accepted by `iptables-restore` and by A4's
  table check (`^\*` count).

## Open items

For A4:

- Warning lines (`warning: ...`) can precede `revision=<n>` on success;
  `render_revision` and `render_error` already handle that. A4 may want to
  log them.
- The binary also links `golang.org/x/sys/unix`; the Docker build stage
  needs module download for it (it is in `go.sum`), and no new package
  path joins `a2ahub_build_inputs.txt`.
- The proxy exits 1 if `ENCLAVE_A2A_PROXY_UID` is set and differs from its
  euid (guards against a supervisor that forgot `su-exec`).

For A7: `ENCLAVE_A2A_HUB_PORT` must equal the snapshot `hubPort`, otherwise
the proxy refuses every revision (the card URLs and the rules depend on it).
Also set `ENCLAVE_A2A_MAX_REQUEST_BYTES` (CR-A3-1).

For A10:

- The forwarded headers are as listed above. A card fetch carries the
  outbound token, the principal headers and both A2A headers.
- Keepalives are the SSE comment `: keepalive`.
- Any non-200 answer from the adapter becomes -31001 with
  `metadata.httpStatus`, so a 401 for a bad outbound token is visible to
  the caller as a delivery error.

For I2:

- Measure, in a real hub namespace on both engines: revocation close
  latency through the proxy alone, `TCP_USER_TIMEOUT` detection of a paused
  orchestrator through the liveness stream, and the full supervisor plus
  proxy commit with the A4 image built from this branch.
- The SSE splitter treats LF and CRLF line ends. A bare CR terminator from
  an adapter is relayed but not split into events (A10 uses `a2a.SSEWriter`,
  which writes LF).
