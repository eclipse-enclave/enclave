# G1: multi-harness selection and retention integration

Date: 2026-11-05. Worktree `a2a-multi-harness`, branch
`feat/a2a-multi-harness`, based on `a2a` at `9a89bdf0`. Implementation was
prepared without changing the original worktree or branch. The maintainer
subsequently requested one local commit and integration into `a2a`; that
integration is recorded in Git history. No push was requested.

## Scope

CR-MH-1 through CR-MH-4 in `interfaces.md` record the multi-harness scope
extension. The existing Claude selection switch now also constructs Codex,
Copilot and Pi drivers by validated event format. The hub, credentials,
topology, wire schema, task handles and public CLI flags are unchanged.
Each tool provides its own headless command, version gate, session handling,
MCP orchestrator configuration and group-only provenance skill.

The shipped-spec factory test loads all four real profiles, serializes the
runtime harness envelope, selects the driver and checks worker permission
bypass. Native spec surface goldens were regenerated for Codex, Copilot and
Pi. `make generate` leaves generated option/CLI code unchanged.

## Pre-spawn inventory

Probes found prompt/reply data in native shared SQLite databases. Copilot
therefore isolates its native home per context, Codex redirects SQLite into
private per-turn directories while resuming from rollouts, and Pi isolates
native session directories. Whole shared databases are never deleted as a
per-context cleanup operation.

Optional `a2aagent.InvocationInventory` lets a driver expose storage paths
after `Command`. The executor persists them before `Start`, including when
the harness has not chosen its session ID yet, and refuses to spawn if that
write fails. Claude also implements it for its pre-bound transcript paths.
Regression tests cover a crash before any event for both caller-chosen and
harness-chosen IDs, plus inventory-write failure preventing execution.
`Outcome.Transcripts` still adds dynamically discovered paths; the remaining
dynamic-path part of CR-A9-2 is not claimed solved.

## Deliberate exclusions

OpenCode's real CLI supports stdin, resume and upstream MCP, but its shared
transcript database has no safe context-scoped deletion through the current
file-inventory interface. No worker or automatic orchestrator integration is
shipped for it. Theia's IDE entrypoint provides no headless harness protocol.
Their feasibility findings are in `P2-opencode.md`. Neither was given a dummy
worker spec or an unsupported decoder registration.

The original v1 VM/security gates, experimental markers and deferred issues
remain distinct from this change. In particular, no claim is made that
Podman's older `isolate=true` mode provides `isolate=strict` isolation.
