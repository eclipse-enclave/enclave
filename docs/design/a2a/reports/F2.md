# F2 report: A2A hub image packaging (CR-A4-4)

Branch `a2a-f2`, based on `a2a` at `d99066e`.

## Summary

`gateway.EnsureA2AHubImage` now finds its inputs in every asset root, not
only in a source checkout.

- **Embedding** (`assets_embed.go`): adds `Dockerfile.a2ahub`,
  `a2ahub-entrypoint.sh`, `all:cmd/enclave-a2a-hub`, `all:internal/a2ahub`
  and `all:internal/peergroup`. The other hub inputs (`go.mod`, `go.sum`,
  `internal/a2a`, `internal/logx`, `internal/model`, `internal/util`) were
  already embedded.
- **Inventory test** (`assets_test.go`): checks all three build-input lists
  in both directions.
  - Every listed path is embedded, and its content matches the checkout.
  - Every embedded file under `cmd/` and `internal/` belongs to a listed
    path, so the embed list cannot carry Go sources that no image build
    stages.
  - `Dockerfile.a2ahub` and `a2ahub-entrypoint.sh` are in the required
    asset list.
- **Packages**: `debian/rules`, `packaging/rpm/enclave.spec` and
  `scripts/verify-package-assets.sh` install or verify `Dockerfile.a2ahub`
  (0644) and `a2ahub-entrypoint.sh` (0755), and they loop over
  `internal/gateway/a2ahub_build_inputs.txt` next to the other two lists.
  The verify script compares both files byte for byte and checks that the
  entrypoint is executable.
- **Standalone smoke** (`scripts/smoke-standalone-binary.sh`): checks that
  the extracted asset cache contains `Dockerfile.a2ahub`,
  `a2ahub-entrypoint.sh` and `internal/a2ahub/serve.go`.
- **Version pins** (`scripts/check-versions.sh`):
  - `KNOWN_PINS` covers the two `FROM` lines of `Dockerfile.a2ahub`. It
    also covers `a2aAgentBuilderImage` in `internal/app/a2a_agent_build.go`
    (A14), which the offline check reported as uncovered too.
  - A new lockstep check requires one `golang` ref and one `alpine` ref
    across `Dockerfile.gateway`, `Dockerfile.a2ahub` and
    `internal/app/a2a_agent_build.go`. Since the gateway pins are already in
    the Go toolchain, Alpine version and Alpine digest groups, this ties the
    hub and agent builders to those groups. The check uses `git grep`
    because `scripts/check_versions_test.go` builds a fixture without the
    A2A files, and `extract` would abort on a missing file.
  - The Go toolchain update and problem messages now name
    `Dockerfile.a2ahub` as well.

The extracted `a2ahub-entrypoint.sh` gets mode 0644, because
`appassets.FileMode` does not list it as executable. That is harmless: the
build copies it in and runs `chmod a+rx`. Packages install it as 0755 so
it matches the gateway entrypoint.

  gosec, shellcheck), `make check-license-headers`: pass.
- `scripts/check-versions.sh --offline`: 0 problems.
  - Negative check: changing the alpine digest in `Dockerfile.a2ahub`
    reports `alpine image is pinned 2 ways`.
- Negative check for the inventory test: removing `internal/peergroup` from
  the hub list fails with `embedded internal/peergroup/... is in no
  build-input list`.
- `scripts/smoke-standalone-binary.sh bin/enclave`: pass.
- `make deb-quick`: built. The extracted `.deb` passed
  `scripts/verify-package-assets.sh <root> usr/share/zsh/vendor-completions`.
  It ships `Dockerfile.a2ahub`, `a2ahub-entrypoint.sh` (0755),
  `cmd/enclave-a2a-hub`, `internal/a2ahub` and `internal/peergroup`.
- rpm: untested, because `rpmbuild` is not installed here.
- Hub image from embedded assets:
  - Copied the `make build` binary to `/tmp`, ran it with a temporary
    `XDG_CACHE_HOME` to extract the asset root, and staged exactly
    `a2aHubBuildPaths()` from that root, as `prepareA2AHubContext` does.
  - `docker build -f Dockerfile.a2ahub` succeeded on Docker 29.9.2.
  - In the image, `enclave-a2a-hub` printed its usage, and both binaries
    in `/usr/local/bin` are 0755.
  - No CLI path calls `EnsureA2AHubImage` yet (A7), so the build was driven
    by hand. A temporary `HOME` was not possible in this sandbox.
