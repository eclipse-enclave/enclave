Date: 2026-11-05. Branch `feat/a2a-multi-harness`, separate worktree from
`a2a`. Docker server 29.9.3; rootless Podman 4.9.3 with netavark 1.4.0.
All results below are actual model-backed container runs, not fixture drivers.

The lead discovered peers through the shipped MCP integration, sent the
brief to both reviewers, waited for their task handles, exchanged findings
for rebuttal in the original contexts, verified survivors with read-only
checks and returned one ranked list. Each adapter's authoritative task
records contain two completed, termination-confirmed tasks in one context
from the lead principal. Leads actually used MCP; no host send shim drove
their reviews. Final syntheses corrected some reviewer claims rather than
simply concatenating their output.

The final Podman/Codex run also mechanically compared the initial task
`contentHash` values (equal, proving the same initial brief), checked the
sentinel only in the final assistant message, and checked all inventoried
transcripts were removed before deleting the isolated test roots. The
Podman/Claude run also exercised the strengthened final-message and
pre-root-deletion inventory checks. Earlier Docker runs used the earlier
smoke revision; their final messages and task/context counts were checked
again from saved evidence. After the matrix, independent engine queries
found no `a2a-mixed-*` containers or networks on either engine.

## Reproduction

Build first, then run these separately:

```sh
make build
ENGINE=docker scripts/a2a-smoke.sh mixed_review
ENGINE=docker A2A_SMOKE_ORCHESTRATOR_TOOL=codex scripts/a2a-smoke.sh mixed_review
ENGINE=podman scripts/a2a-smoke.sh mixed_review
ENGINE=podman A2A_SMOKE_ORCHESTRATOR_TOOL=codex scripts/a2a-smoke.sh mixed_review
```

`scripts/a2a-mixed-smoke.sh` owns the mixed scenario; the original smoke
dispatches `mixed_review` to it without changing the original Claude-only
lifecycle steps. These are billed runs. The script creates a temporary Git
project containing a deliberately buggy path-containment function, copies
only shared Claude/Codex auth and Enclave secrets into private XDG roots,
and uses a random group prefix. The host's auth and configuration are never
mounted writable. Claude uses `ANTHROPIC_MODEL=haiku` by default.

The foreground lead runs under a PTY because orchestrator sessions require
one, with a 10-minute deadline. JSONL and engine/startup logs are retained
in the printed scratch directory; copied credentials/state are removed
after successful teardown. If teardown fails, lifecycle metadata is retained
for a scoped retry while copied upstream credentials are scrubbed. The
cleanup trap is installed before any credential copying.

When iterating on the smoke itself, run an immutable copy to avoid changing
a file Bash is still executing (set `CLI_BIN` to the absolute built binary).
The final Podman runs used such snapshots under
`/tmp/enclave-a2a-multi.r2y5RJ/`. Initial smoke-development attempts caught a
missing PTY and a concurrently edited shell script; those setup failures are
not represented as harness failures or included as passing matrix runs.

## Boundaries

- Podman emitted the existing warning that netavark 1.4.0 supports only
  `isolate=true`, not `isolate=strict`. This validates mixed-harness
  functionality in that mode, not strict isolation from non-isolated
  bystander networks. No firewall/isolation guarantee was widened.
- Copilot and Pi have actual native-harness protocol, resume, cancellation
  and MCP probes against local test providers; this matrix does not claim
  model-backed container acceptance for those tools. Copilot's live GitHub
  credential-gated test remained skipped without an exported token.
- Docker userns-remap, Podman strict isolation, SELinux/rpm and the original
  v1 VM-only gates remain outstanding, as does the original paused-lead
  detection limitation. No experimental marker was removed.

See `G1.md` for full build/test/lint results and the retention integration,
and `P2-*` / `A9-*` for the per-harness evidence.
