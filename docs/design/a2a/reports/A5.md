# A5 report: gateway overlay and rules

Branch `a2a-a5`, based on `33158d4`.

## Summary

- `gateway-entrypoint.sh` reads `/etc/enclave-a2a-overlay/overlay.json`
  (`peergroup.GatewayOverlayPath`) at start and at the beginning of every
  SIGHUP reload. A missing file leaves every rule and the dnsmasq config
  byte-identical to today and logs no marker (tested).
- `active: true` adds, in the same pass that rebuilds the rest of the policy:
  one INPUT rule (omitted for `adapterPort: 0`), one OUTPUT filter rule, one
  nat OUTPUT `RETURN` ahead of the proxy rules, and `host-record=<dnsName>,<hubAddress>`
  appended to the staged dnsmasq config before `dnsmasq --test`. ip6tables gets
  nothing. `active: false` installs none of them, so the reload removes them.
- Markers are the four strings of interfaces.md section 4, exactly one per
  read, logged before `Reload completed` / `Gateway ready`. Validation
  failure and every later failure of the same pass (bundle validation,
  install, ipset swap, firewall, child restart) log their marker and then take
  the existing fail-closed shutdown path.
- The overlay parser is POSIX shell (no jq in the image). It rejects files
  over 4 KiB, any backslash, duplicate keys, `schemaVersion` other than `"1"`,
  non-canonical integers, ports outside 1..65535 (`adapterPort` may be 0),
  hub addresses that are not unicast dotted quads (0/8, 127/8 and 224/3
  rejected), and DNS names outside `[a-z0-9-]` labels. Values reach iptables
  and dnsmasq only after these checks. Inactive overlays need only
  `schemaVersion`, `generation` and `active`.
- `runtime-assets/net.sh` gains `enclave_route_interface_ipv4`, which resolves
  the `<bridge if>` of the INPUT rule with `ip -4 route get <hubAddress>`
  (busybox `ip` in the gateway image). No route, a `lo` answer or a missing
  helper is an apply failure.
- Go (`internal/gateway`):
  - `StartConfig.A2AOverlayDir`: when set, it must be an existing directory
    and is bind-mounted read-only at `peergroup.GatewayOverlayDir`. When
    empty, there is no mount and nothing changes.
  - `ReloadOverlay(ctx, containerID, generation uint64) error` sends SIGHUP
    and waits. This is the reload wait variant that A7's
    `ReloadGatewayOverlay` wraps.
  - `WaitForOverlay(ctx, containerID, generation, since)` covers the
    start-time wait if A7 wants one. `Gateway ready` already implies the
    marker.
  - `OverlayLogOutcome(logs, generation)` is the pure matcher. It returns
    success on `applied` or `cleared` for that generation, and an error on
    `validation failed`/`apply failed` for that generation or on
    `validation failed (generation=unknown)`. A gateway exit or a 15 s
    timeout is also an error.
  - The engine-facing code sits in `gateway.go` because
    `internal/arch` allows only that file of the package to import
    `internal/docker`.

## Rule set as rendered

Live output from `enclave-gateway-claude:latest` with this branch's scripts
mounted over the image's copies, session subnet `172.29.77.0/28`, hub at
`.14`, worker overlay (A2A lines marked `<-`):

```text
-P INPUT DROP
-A INPUT -i lo -j ACCEPT
-A INPUT -m state --state RELATED,ESTABLISHED -j ACCEPT
-A INPUT -s 172.29.77.14/32 -i eth0 -p tcp -m tcp --dport 41821 -j ACCEPT   <-
-P OUTPUT DROP
-A OUTPUT -m state --state RELATED,ESTABLISHED -j ACCEPT
-A OUTPUT -o lo -j ACCEPT
-A OUTPUT -d 172.29.77.14/32 -p tcp -m tcp --dport 41820 -j ACCEPT           <-
... (resolver, ipset and proxy rules unchanged)
nat:
-A OUTPUT -d 172.29.77.14/32 -j RETURN                                        <-
-A OUTPUT -p tcp -m tcp --dport 80 -m owner --uid-owner 101 -j RETURN
-A OUTPUT -p tcp -m tcp --dport 443 -m owner --uid-owner 101 -j RETURN
-A OUTPUT -p tcp -m tcp --dport 80 -j REDIRECT --to-ports 8080
-A OUTPUT -p tcp -m tcp --dport 443 -j REDIRECT --to-ports 8443
dnsmasq.conf tail:
host-record=a2a.enclave,172.29.77.14                                          <-
```

Observed on that container:

- `a2a.enclave` resolves to the hub, and `x.a2a.enclave` gets NXDOMAIN
  because `host-record` overrides `address=/#/` for the exact name only.
- The gateway reaches hub:41820 by IP and by name. hub:41822 is dropped.
- The hub reaches the gateway's port 41821. A bystander on the same bridge
  is dropped.
- A cleared overlay (gen 4) followed by SIGHUP removed all three rules and
  the record, and logs `A2A overlay cleared (generation=4)` before
  `Reload completed (generation=g1)`.
- An invalid overlay logs `validation failed`, then `Reload validation failed`,
  and the gateway exits 1.
- A temporary live test called `ReloadOverlay` against the container. It
  returned nil for a cleared gen 8 and an error for an invalid gen 9.
- A gateway without the overlay mount logged no A2A line at start or on
  reload.

## Deviations and interpretations (no CRs)

No interface names, paths or marker strings changed. These points fill gaps
in the text without contradicting it:

1. **NAT exemption only when the transparent proxy is enabled.** That is the
   only mode with REDIRECT rules, and the only mode where nat OUTPUT is
   flushed and rebuilt. Without the proxy, a RETURN would be meaningless and
   would pile up on every reload. No Go path sets `PROXY_ENABLED=false` today.
2. **Bundle failures after a valid overlay read log `apply failed`.** This
   keeps the rule of exactly one marker per read, and the host never waits
   on a gateway that is shutting down.
3. **Overlay validation failure also logs the bundle's
   `Reload validation failed (generation=<bundle gen>)`.** Without it, a
   concurrent `enclave network` reload waiter would only learn of the failure
   from the gateway exit.
4. **"Atomic" means the same flush-and-rebuild pass as the rest of the
   policy,** under DROP policies, as today. It is not `iptables-restore`.
   Moving the whole policy to `iptables-restore` would be a separate
   hardening.

## Open items for P1-D / P1-P

- **Overlay file readability.** The gateway runs as root in the container
  (`0:0` in the keep-id user namespace under rootless Podman). A2's
  `WriteOverlay` mode must stay readable there. Under Docker
  `userns-remap`, a 0600 file owned by the host user would read as
  `validation failed (generation=unknown)`.
- **Directory bind on rootless Podman with SELinux relabel.** Confirm that
  `docker.SplitMountsForSELinux` handles the new mount and that a host
  rename is visible on the next reload.
- **`-i` on netavark.** Confirm that `ip -4 route get <hub>` answers the
  session interface (`eth0`) after the hub joins, under Podman and Docker.
- **`isolate=true` (CR-1).** Record that a bystander cannot reach the adapter
  port: the INPUT rule is scoped by both `-i` and `-s <hub>`.
- **Long-lived streams across reload.** Measure whether the SSE control and
  liveness streams survive a gateway reload. During the flush window,
  established packets fall to DROP and TCP retransmits them.
- **Connections after a clear.** Established connections to or from the hub
  survive a clear through the ESTABLISHED,RELATED rules. Leave relies on the
  hub-side conntrack flush and on the disconnect. P1 should confirm that
  this ordering is enough.
