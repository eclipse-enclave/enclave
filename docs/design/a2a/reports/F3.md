### Credentials (CR-A13-1)

Both take the group lock (blocking on `ctx`, like join and leave) and run no
reconcile.

- `IssueHostCredential`:
  - Refuses when the hub is not running or carries another group generation:
    a commit could not happen, so the call fails at once instead of after
    the commit timeout.
  - Drops expired credentials, adds the new hash, then publishes and commits
    one revision (purpose `credential`) through `commitRevision`, which uses
    the engine-side secrets owner and waits up to `CommitTimeout` for both
    acks.
  - On failure the hash is removed from the record, a `snapshot-commit`
    obligation is added, and `Pending` stays set, so reconcile replaces the
    published revision. The token never leaves the call.
- `RevokeHostCredential`:
  - A hash that is not on record (expired, or another group generation) or
    a missing group returns nil without publishing.
  - Running hub: commit as above. A commit failure leaves a `snapshot-commit`
    obligation and returns an error; the record no longer lists the hash.
  - Stopped hub: publish only, like leave (A7): a restarted hub loads
    `current`, and reconcile commits it.
- A successful commit publishes the record's whole membership, so it also
  settles any earlier `snapshot-commit` obligation. Both functions clear
  those, the same way reconcile does after its republish.

### Hub call (CR-A13-2)

`HubCall` validates the path (leading `/`, no whitespace) and runs
`exec --interactive --user 65532 <hub> /usr/local/bin/enclave-a2a-hub call
<path>` through `dockercmd.ExecStream`. The hub name is `ref.Name`, else
`ref.ID`, else `enclave-a2a-hub-<group>`.

`ExecStream` returns stdout as it arrives (a `StdoutPipe`, nothing is
buffered). When the command fails, the read that reaches the end of stdout
returns a `cliError` carrying stderr in place of `io.EOF`, so output printed
before the failure is still delivered. `Close` cancels the CLI process and
waits; `WaitDelay` (5 s) keeps a stdin reader that never ends from blocking
`Close`.

### Session identity (CR-A13-3)

`sessionFromSummary` fills `Session.PeerGroup` from the five `enclave.a2a.*`
labels when `enclave.a2a.group` is set. This covers `List` and `Inspect`.

`ps --json` (`collectPSA2AObjects(state *a2aState, sessions, now,
staleness)`):

- Sessions without the label: `a2a: null`, as before.
- The identity fields (`group`, `groupGeneration`, `role`, `generation`)
  come from the labels.
- `hub`, `port`, `snapshotRevision` and the tri-state fields come from the
  group record, but only when the record has the label's group generation
  and lists the member with the label's member generation.
- Otherwise (record gone, unreadable, another group generation, or the
  member generation left): the label identity, `hub`, `port` and
  `snapshotRevision` null, and all three tri-states `unknown` with null
  `At` and `Source`.
- Each group record is read once per `ps`. When the host home cannot be
  resolved, the objects carry only the label fields.

## App changes

- `engineA2AHostAccess` is a thin adapter. `Issue` calls
  `IssueHostCredential` and reads the exact `expiresAt` back from the record
  for the revocation warning (falling back to issue time plus lifetime).
  `Revoke` calls `RevokeHostCredential`. `Call` builds the stdin (credential
  line, then body) and calls `HubCall`.
- `newEngineA2AHostAccess` takes both from `a2aNewLifecycle`: the
  `*PeerGroups` through a small `a2aHostCredentials` interface, and the
  `*Backend` as `a2aHubCaller`.
- No `os/exec` or engine name is left in `internal/app/a2a_host.go`.
- `command_ps.go`: one line, `psA2AObjects(opts, sessions)`.

## Measured latency

The engine test runs five issue and revoke rounds against one committed
orchestrator member, with the stand-in hub:

| Engine | Issue (mean) | Revoke (mean) | Range |
| --- | --- | --- | --- |
| Docker 29.9.2 rootful (secrets helper container per revision) | 274 ms | 290 ms | 254 to 321 ms |
| Podman 4.9.3 rootless (`podman unshare chown`) | 209 ms | 218 ms | 182 to 275 ms |

So a host verb now costs about 0.5 s for credentials (issue plus revoke),
versus a full reconcile per issue and per revoke on the interim path.
These numbers use the stand-in hub's ack. The real hub's ack latency is not
measured here (no real hub image on this host); I2 should repeat the
measurement with one.
