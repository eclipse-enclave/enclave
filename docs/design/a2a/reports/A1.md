# A1 report: protocol package

Package A1, Wave 1. Branch `a2a-a1`, based on `33158d4`. Owned files:
`internal/a2a/` and this report.

## Summary

Every `panic("not implemented")` body in `internal/a2a` is implemented:

- `Error.Error`, `NewError` (one `google.rpc.ErrorInfo` with `ErrorDomain`).
- `DecodeResult` / `EncodeResult`: member-discriminated oneof. Exactly one of
  `task`, `message`, `statusUpdate`, `artifactUpdate` must be present; zero or
  several is an error. Unknown sibling members are ignored (spec 5.7) and a
  `null` member counts as absent (ProtoJSON).
- `SSEWriter`: sets `Content-Type: text/event-stream`, `Cache-Control:
  no-store`, `X-Accel-Buffering: no`; one `Write` plus `Flush` per event or
  comment; multi-line data is split into `data:` lines; IDs and event names
  with line breaks are refused so a caller cannot inject fields.
- `SSEReader`: WHATWG event-stream parsing (CRLF, LF and CR terminators,
  leading BOM, comments, one leading space stripped, `id` persistence and the
  NUL rule, numeric `retry`, events with an empty data buffer not dispatched).
  `maxEventBytes` bounds all bytes of one event, including comments; a
  non-positive value means 1 MiB. A stream ending inside an event returns
  `io.ErrUnexpectedEOF`, a clean end `io.EOF`; errors are sticky.
- Handles: `String`, `ParseTaskHandle`, `ParseContextHandle`. The worker must
  look like a sanitized session name (`[a-z0-9-]`, 1 to 32, no leading or
  trailing `-`), the generation must be 16 lowercase hex characters
  (interfaces.md Conventions), and the ID is everything after the third colon
  and must be non-empty.

Golden fixtures live in `internal/a2a/testdata/`: `spec-<section>-*.json`
are copied from the v1.0.1 specification examples (sections 4.6.1, 4.6.2,
6.1, 6.3, 6.7, 6.8, 8.5, 9.4.1, 9.4.3, 9.4.5, 9.4.6, 9.4.8, 9.5, and
`spec-9.4.2-stream.sse`, which wraps the 6.2 payloads in the 9.4.2
framing). `enclave-*.json` are modeled on interfaces.md section 11 (card,
streaming send with retry metadata, terminal task with termination and
principal, queued status update, artifact update, message result, delivery
error). Tests cover decode and round trip for every object type, exact
re-encoding where the fixture sets every required field, encoder goldens for
the enclave card and `NewError`, `TASK_STATE_UNSPECIFIED` rejection on decode
and encode, and the oneof with zero or two members.

## Spec ambiguities found

1. **Spec examples omit required fields.** 6.2 sends `artifactUpdate` and
   `statusUpdate` without `contextId` and the artifact without `artifactId`;
   6.3 and 4.6.1 send messages without `messageId`. Decoding is therefore
   lenient on required fields; `Message.Validate` enforces them where enclave
   needs it. Other required-field checks (task `id`, event `taskId`) are left
   to the consumers.
2. **Two spec examples are not valid JSON**: 4.6.1 (trailing comma in the
   card) and 6.7 (missing and trailing comma in the file part). The fixtures
   repair them.
3. **ErrorInfo domain for A2A codes.** Spec 9.5 shows `domain:
   "a2a-protocol.org"` with `reason: "TASK_NOT_FOUND"` for `-32001`.
   `NewError` always writes `ErrorDomain`, so it fits enclave codes. For A2A
   codes, consumers should either send no `data` (a plain `&Error{...}`) or
   agree on a domain. Suggest the coordinator fix this for A3 and A10.
4. **`A2A-Version` as a query parameter.** Spec 3.6.1 lets clients send it as
   a request parameter instead of a header (the example is HTTP+JSON GET).
   `CheckVersion` reads the header only, which matches the JSON-RPC binding
   (9.2: service parameters MUST be headers).
5. **Version error shape.** Spec 6.4 shows an HTTP 400 `problem+json` body
   for HTTP+JSON. For JSON-RPC, interfaces.md section 11 (HTTP 200 with a
   `-32009` error) stands.
6. **Empty SSE data.** A `data:` line with an empty value is dispatched as an
   event with empty data (WHATWG); only an event with no `data` line is
   dropped. `WriteEvent` with empty `Data` therefore produces an event with
   empty data, not nothing.
7. **`Event.Retry`.** In WHATWG, `retry` sets the reconnection time and is not
   part of the event. `SSEReader` reports it on the event in whose block it
   appeared. Enclave streams do not use it.
8. **Handle IDs with any character.** Interfaces.md says the ID "may contain
   any character", so control characters and invalid UTF-8 are accepted.
   Through `MarshalText` and JSON, invalid UTF-8 is replaced with U+FFFD, so
   such a handle does not survive a JSON round trip. The adapter issues IDs,
   so this only matters for client-typed garbage, which then fails as an
   unknown task.

## Open items

- Worker-name validation in handles approximates `model.SanitizeSessionName`
  without importing `internal/model` (it accepts consecutive dashes). If A2
  publishes a shared validator, handles could use it.
- `DecodeParams` puts the `encoding/json` error text in the `-32602` message;
  it names Go types. Harmless for enclave clients; A10 may prefer a fixed
  message.
- The ErrorInfo domain for A2A-range codes (ambiguity 3) needs a decision
  before A3 and A10 emit them.
