# A4 report: hub image and supervisor

Branch `a2a-a4`, based on `6fdb667`.

## Summary

- `Dockerfile.a2ahub`: a build stage on the gateway's pinned
  `golang:1.26.10-alpine3.24` builds `./cmd/enclave-a2a-hub`, and the runtime
  stage is the gateway's pinned `alpine:3.24` with `conntrack-tools`,
  `iproute2-ss`, `iptables` (includes `ip6tables`), `iputils-arping` and
  `su-exec`. It holds `/usr/local/bin/enclave-a2a-hub` (on `PATH` for
  `enclave-a2a-hub call`) and `/usr/local/bin/a2ahub-entrypoint.sh` as
  `ENTRYPOINT`. "Gateway base" here means the same pinned images. The
  per-profile `enclave-gateway-<profile>` image is not used as a parent,
  because it is profile-specific and ships dnsmasq and the MITM proxy.
- Size with a stand-in binary: 31.6 MB (binary 8.8 MB). A3's real binary
  will change the binary part of that.
- `a2ahub-entrypoint.sh`: a POSIX shell root supervisor following the
  gateway pattern (see the sequence below). It is shellcheck clean.
- `internal/gateway/a2ahub_build.go` builds the image, hashes its inputs and
  tags it the way the gateway image does. `a2ahub_build_inputs.txt` is the
  list of staged inputs.

## Supervisor sequence

Start (PID 1, root):

1. Load fixed policies with `iptables-restore` and `ip6tables-restore`:
   INPUT, FORWARD and OUTPUT DROP, with `lo` accepted (Q9). This runs before
   anything reads `current`.
2. Check that `net.ipv4.ip_forward` is 0, and try to write 0 if it is not.
   If it is still on, the start fails (CR-P1P-2 has A7 set the sysctl).
3. Generate the epoch: 16 hex characters from `/dev/urandom`.
4. Start the proxy with `su-exec 65532:65532 env ENCLAVE_A2A_HUB_EPOCH=<epoch>
   enclave-a2a-hub proxy` (uid from `ENCLAVE_A2A_PROXY_UID`, see CR-A4-2).
5. Wait until `proxy.json` carries an epoch other than the one it had
   before the proxy started. This works whether or not the proxy adopts the
   supervisor epoch. The timeout is 30 s. A proxy that exits or stays silent
   fails the start.
6. Apply `current` (below), then send gratuitous ARP. "Hub ready" is logged.

Apply (at start and on every SIGHUP; a SIGHUP is a flag polled every 0.1 s,
the same as the gateway):

1. `enclave-a2a-hub render-rules --snapshot-dir <dir>`. If it exits non-zero,
   the revision is rejected. The rejected revision is taken from
   `revision=<n>` on stderr, falling back to the name of the `current`
   link target. The error is the last other stderr line.
2. The supervisor refuses rendered rules that are not exactly one `*filter`
   table with `:INPUT DROP`, `:FORWARD DROP` and `:OUTPUT DROP` (defense in
   depth against an open policy). It then inserts `-I INPUT 1 -i lo` and
   `-I OUTPUT 1 -o lo` accepts before `COMMIT`.
3. `iptables-restore` runs once and is atomic. If it fails, the revision is
   rejected and the old rules stay in place.
4. It diffs peer addresses against the last applied revision: INPUT `-s`
   and OUTPUT `-d` (`/32` stripped). For each removed address it runs
   `ss -K dst <addr>`, then `conntrack -D -s <addr>` and
   `conntrack -D -d <addr>` (CR-P1D-1 order: rules, socket abort, flush).
5. It writes `supervisor.json` with the applied revision and
   `rejectedRevision` 0, or on a rejection keeps `appliedRevision` and sets
   `rejectedRevision` and `error`. The write goes to a temp file in the
   status directory, then `sync` of the file, rename, and `sync` of the
   directory. The error is cut at 512 bytes and JSON-escaped.
6. On SIGHUP only: `kill -HUP` to the proxy. This happens after the status
   write, whether the revision was applied or rejected, because the proxy
   decides on its own.
7. Gratuitous ARP (`arping -U -c 1 -w 1 -I <if> <addr>`) for every IPv4
   address on every non-`lo` interface. The list is read fresh from
   `ip -o -4 addr show` each time, so no interface names are cached. The
   pings run in parallel and the supervisor waits for them. Deviation from
   the brief: ARP runs after the status write and signal, not before, so
   commit latency does not include `arping`.

Exit: the supervisor exits 1 when the proxy exits, when start fails, or when
it cannot write `supervisor.json`. On TERM or INT it sends TERM to the proxy
and exits 0.

## Exported Go API (for I1)

```go
const A2AHubImage = "enclave-a2a-hub:latest"
const A2AHubLabelHash = "enclave.a2ahub.hash" // image label, outside the enclave.a2a.* container label namespace

type A2AHubImageConfig struct {
	Paths        model.Paths // only AppRoot is used
	Home         string      // image build lock
	ForceRebuild bool
	NoRebuild    bool
}

func EnsureA2AHubImage(ctx context.Context, cfg A2AHubImageConfig) (string, error)
```

`EnsureA2AHubImage` hashes `Dockerfile.a2ahub`, `a2ahub-entrypoint.sh` and
every path in `a2ahub_build_inputs.txt` (excluding `_test.go`), the same way
as `gateway_proxy_build_inputs.go`. It compares the hash with the image label
and builds under `config.AcquireImageBuildLock` when the label differs or
`ForceRebuild` is set. With `NoRebuild` it only checks that the image exists.
It returns the tag, which I1 puts into `backend.HubSpec.Image`. The build
context is a temporary directory that holds only the hub inputs. Like the
gateway build, it retries once on the host build network.

Build inputs: `go.mod`, `go.sum`, `cmd/enclave-a2a-hub`, `internal/a2a`,
`internal/a2ahub`, `internal/logx`, `internal/model`, `internal/peergroup`,
`internal/util`. `internal/peergroup` pulls in `model`, `logx` and `util`
(this was found when the live build failed). The hub-only packages are not
gateway inputs (tested), so hub changes do not rebuild gateway images.

## Tests

- `a2ahub_entrypoint_test.go` sources the shipped script without `main`,
  the same way as `firewall_test.go`. Shell functions mock `render-rules`,
  `ss`, `conntrack`, `arping`, `ip` and `kill -HUP`. `iptables-restore`,
  `ip6tables-restore` and `su-exec` are executables on `PATH` (sh function
  names cannot contain hyphens). Covered:
  - Start order: default deny, then proxy start, then proxy status, then
    the first render.
  - The proxy runs as `65532:65532` with the supervisor epoch.
  - The status file parses as `peergroup.StatusFile`.
  - Start fails without a fresh proxy status (exit, stale epoch, silence)
    and when forwarding is on.
  - Removal: `iptables-restore`, then `ss -K`, then both conntrack deletes,
    for the removed address only.
  - Loopback accepts are injected.
  - Rejection, with the last rules kept and an escaped error, for five
    causes: refused render, refused render without a revision, open policy,
    extra table, failing `iptables-restore`. The next apply diffs against
    the last applied revision.
  - SIGHUP is forwarded after the status write on both applied and
    rejected reloads. ARP goes to non-`lo` interfaces, and the `@ifN`
    suffix is stripped.
- `a2ahub_build_test.go`:
  - The hash tracks the Dockerfile, the entrypoint, `go.sum` and package
    sources, and ignores `_test.go` and non-input packages.
  - A missing input fails.
  - The staged context holds only hub inputs.
  - `EnsureA2AHubImage`: builds a missing image, skips a current one,
    rebuilds when forced, and with `NoRebuild` errors on a missing image.
  - The manifest path-existence test and the `go list -deps` coverage test
    are the same checks as the gateway's. They skip until
    `cmd/enclave-a2a-hub` exists on the branch and then run as-is.

## Live image test: ran (rootful Docker 29, kernel 6.17)

I built the image from a temporary context outside the repo. It contained a
stand-in `cmd/enclave-a2a-hub` (`render-rules` and `proxy` on
`peergroup.LoadCurrent` and `WriteStatus`) and real snapshots published with
`peergroup.SnapshotPublisher`. `secrets.json` was chowned to 65532 with mode
0400 by an engine-side container. The hub ran with the CR-P1P-2 flags
(`--cap-drop ALL` plus the six capabilities, `--read-only`,
`no-new-privileges`, `ip_forward=0`), `--tmpfs /run --tmpfs /tmp`, and two
member bridges. Nothing from the stand-in was committed. Results:

| Check | Result |
| --- | --- |
| Start, revision 1 | both status files applied 1, same epoch |
| Join after `network connect`, SIGHUP | committed in 131 to 137 ms |
| Rules | INPUT `-i <if> -s <gw> -d <hub> --dport 41820` per member, OUTPUT `--dport 41821` to the worker only, lo first, IPv6 all DROP |
| Supervisor | uid 0, CapEff `0x30e4`, NoNewPrivs 1; reads 0400 `secrets.json` (DAC_READ_SEARCH) |
| Proxy | uid/gid 65532, CapEff 0, NoNewPrivs 1; cannot run iptables or replace `supervisor.json` |
| Reachability | orchestrator to hub open; proxy to worker adapter open; proxy to orchestrator `:41821` and to `1.1.1.1:443` blocked |
| Removal with an open member-to-hub connection | committed in 132 to 240 ms; hub socket aborted, worker side has no socket, 0 conntrack entries, new connections blocked |
| Corrupt revision 4 (hash mismatch) | `rejectedRevision` 4 with the reason, `appliedRevision` 3, rules unchanged |
| `docker restart` | new epoch in both files, revision applied in 541 to 611 ms; the orchestrator's neighbor entry already had the new hub MAC (gratuitous ARP), and requests worked at once |
| Proxy killed | hub exits 1 |
| `docker stop` | 228 to 258 ms, exit 0 |

## Change requests

- **CR-A4-1** (`internal/arch/arch_test.go`, owner unassigned): add
  `internal/gateway/a2ahub_build.go` to `dockerImportAllowlist`.
  `TestDockerImportsConfinedToBackendAndCarveOuts` fails until then. It
  is the only failure in `make test` on this branch. The file needs the
  same Docker build and inspect calls that `gateway.go` is allowed to make.
- **CR-A4-2** (interfaces section 6, A1 `internal/a2a/enclave.go`, A3):
  add `ENCLAVE_A2A_HUB_EPOCH` (`a2a.EnvHubEpoch`), set by the supervisor
  for the proxy only. The proxy uses it as its epoch (`hello`, audit,
  `X-Enclave-A2A-Epoch`, `proxy.json`), so the hub has one epoch as P7
  says ("by the hub at start"). The supervisor already exports it. If A3
  generates its own epoch, everything still works, but the two status
  files show different epochs, and "ready when both show a new epoch"
  then has to compare each file against its own old value.
- **CR-A4-3** (interfaces section 11, `render-rules`, A3), a clarification
  of what the supervisor relies on:
  - output is exactly one `*filter` table with `:INPUT DROP [0:0]`,
    `:FORWARD DROP [0:0]` and `:OUTPUT DROP [0:0]` (otherwise refused);
  - peer addresses appear as INPUT `-s <gw>/32` and OUTPUT `-d <gw>/32`
    (the removal diff reads exactly these);
  - ESTABLISHED,RELATED accepts are rendered by A3;
  - loopback accepts are added by the supervisor, so A3 may omit them;
  - on refusal, print `revision=<n>` before the reason when the revision
    is known. Otherwise the supervisor reports the `current` link name,
    which can race with a swap.
- **CR-A4-4** (packaging; root `assets_embed.go`, `assets_test.go`,
  `debian/rules`, `packaging/rpm/enclave.spec`,
  `scripts/verify-package-assets.sh`, `scripts/smoke-standalone-binary.sh`,
  `scripts/check-versions.sh`, `docs/ARCHITECTURE.md`):
  - embed and install `Dockerfile.a2ahub`, `a2ahub-entrypoint.sh` and the
    paths in `internal/gateway/a2ahub_build_inputs.txt`, the way the
    gateway inputs are handled. Until then, `EnsureA2AHubImage` works
    only where `AppRoot` is a source checkout. The default embedded binary
    extracts an asset root without these files, so the build fails with a
    missing-input error.
  - add `Dockerfile.a2ahub` to `KNOWN_PINS` and to the Go toolchain and
    Alpine lockstep groups. `make check-versions` currently reports the
    two `FROM` lines as uncovered pins.
