# A2 report: host state (`internal/peergroup`)

Branch `a2a-a2`, based on `a2a` at `33158d4`.

## Summary

Every stub in `internal/peergroup` is implemented against interfaces.md
sections 1 to 4 and 8. Nothing outside the package changed.

- **Group store** (`store.go`, `lock.go`): `Lock`, `Load`, `Create`, `Save`,
  `Delete`, `List`. `Create` provisions the group generation and the host
  principal (`_host`, its own generation), empties `snapshots/` and
  `status/` and removes `host-secrets/`, so revision numbers and acks never
  span generations; old inventory files and the audit log are kept. `Save`
  refuses to overwrite a record that has a different group generation.
  `Delete` checks the generation, removes `group.json`, snapshots, status and
  host secrets, and removes the group directory once no inventory file is
  left.
- **Snapshot publisher** (`snapshot.go`): staging directory, membership,
  secrets (0400, then the `SecretsOwner` hook), manifest last, fsync of every
  file and of the staging directory, rename to `N`, fsync of the root, then
  the `.current-N` temp symlink is renamed over `current` (relative target)
  and the root is fsynced. The next revision is one above every revision,
  `.staging-*` and `.current-*` name and the `current` target, so a failed
  staging never gets its number reused. `LoadCurrent` refuses a `current`
  that is not a canonical decimal name, verifies both hashes, requires the
  manifest to list exactly the two files, and checks that group, group
  generation and revision agree across directory name, manifest, membership
  and (with `withSecrets`) secrets. Without `withSecrets` it still reads
  and hash-verifies `secrets.json` but does not parse it.
- **Status** (`status.go`): `WriteStatus` (atomic, 0644, fills
  `schemaVersion` and `updatedAt`), `Read` (a file naming the wrong reader
  is an error), `WaitCommitted` (polls; commit when both files carry the
  expected group generation and `appliedRevision >= N`; `rejectedRevision ==
  N` with the expected generation fails at once with `ErrRevisionRefused`;
  timeout and ctx cancel are `ErrNotCommitted`, the latter also wrapping the
  ctx error). Files from another group generation never count either way.
- **Inventory** (`inventory.go`): `Add` writes `admitting` and refuses
  duplicates and store paths that are relative or do not end in the member
  generation. `SetState` accepts only `member` and `eligible` (stamps
  `eligibleAt`). `Remove` is idempotent. An empty file is deleted, then the
  group directory is removed if `group.json` is gone too. `DeleteEligible`
  saves failures in `lastError` and `lastAttemptAt`, keeps those entries,
  returns the joined errors, and skips (with an error) any entry whose store
  path is not scoped to its member generation.
- **Tokens** (`tokens.go`): 32 `crypto/rand` bytes, base64url without
  padding; hash `sha256:<lowercase hex>` of the token string; `Verify` uses
  `subtle.ConstantTimeCompare`. Workers get inbound and outbound tokens,
  orchestrators inbound only; any other role is refused. Host copy of the
  outbound tokens at 0600.
- **Worktree guard** (`worktree.go`): absolute paths only, cleaned, with
  symlinks resolved where the path exists. Same path with both `rw` is
  `ErrWorktreeClash`. Same path with one `ro`, or nested paths in either
  direction, produce warnings.
- **Overlay** (`overlay.go`): `WriteOverlay` is atomic, 0644, and refuses
  generation 0.
- Shared helpers (`fsutil.go`): atomic replace (temp file in the same
  directory, write, chmod, fsync, rename, fsync directory), readers that
  refuse unknown `schemaVersion`, and `ensureDir`, which sets the mode
  explicitly (umask and an existing directory would otherwise keep the wrong
  one).

### Additive API (no existing name, shape or layout changed)

- `Generation.Valid()`, `FormatTimestamp`, `ParseTimestamp` (RFC 3339, UTC,
  seconds), so every consumer writes timestamps the same way.
- `LocalSecretsOwner(uid) SecretsOwner`: the uid parameter the brief asked
  for (see platform notes).
- `MaxInvocationLifetime` (1 h) and `GroupRecord.AddCredential`,
  `RevokeCredential`, `ExpireCredentials`, `CredentialHashes`: keep host
  invocation credentials bounded, hash-only in the record, and unpublished on
  revocation or expiry.
- Doc comments now state that `Current` returns 0 when nothing is published,
  that `Prune` always keeps the revision `current` points at, and that
  `NewSnapshotPublisher` with a nil owner leaves `secrets.json` owned by the
  host user.

## Change requests

- **CR-A2-1** (2026-11-05, A2, section 1 "Retention" and section 8
  `SnapshotPublisher.Prune`). `Prune(group, committed)` could not tell
  which earlier revision committed: the snapshot layout does not record it,
  and `group.json` already holds N by the time `Prune` runs, so a failed
  revision between two commits would have been kept instead of the previous
  committed one. Decision (coordinator): accepted with the parameter. The
  signature is now `Prune(group, committed, previous Revision)`. It keeps
  `committed`, `previous` (when non-zero) and the `current` target, and
  removes everything else. A `previous` that is not below `committed` is an
  error. A7 passes the committed revision it read from the group record
  before the update. interfaces.md section 1 is updated, and
  `TestPruneKeepsCommittedNotFailedRevision` covers the case where
  revision 7 commits, 8 fails and rollback revision 9 commits.

## Platform notes

- **Locking.** The group lock is `<locksDir>/a2a-<group>.lock`. It reuses
  `util.TryAcquireFileLock` (`flock(LOCK_EX|LOCK_NB)` on Unix, `LockFileEx`
  on Windows), so no platform code is duplicated and no dependency is added.
  The lock is polled (10 ms doubling to 200 ms) because a blocking `flock`
  cannot be interrupted by ctx. If ctx has no deadline, a 2 minute default
  applies. Locks belong to an open file description, so two holders in one
  process also exclude each other; tests cover in-process exclusion and a
  real second process (the test binary re-executed as a lock holder). The
  kernel releases the lock when a holder crashes. `flock` on NFS state
  directories is not reliable; that is a pre-existing enclave assumption.
- **Permissions.** `a2a/`, `a2a/<group>/`, `inventory/`, `host-secrets/`:
  0700. `group.json`, inventory files, `outbound.json`: 0600. `snapshots/`
  and revision directories: 0755. `membership.json` and `manifest.json`:
  0644. `secrets.json`: 0400. `status/` and `audit/`: 1777 (sticky). Status
  files and `overlay.json`: 0644.
- **secrets.json ownership.** The publisher writes `secrets.json` as the
  host user with mode 0400 and then calls the `SecretsOwner` hook on the
  staged path, before the manifest is written. `LocalSecretsOwner(uid)`
  chowns from the calling process. That works only as root or with
  CAP_CHOWN. A regular user gets the `EPERM` (wrapped, `errors.Is`-checkable)
  for any uid other than its own; for its own uid the chown is skipped and
  only the mode is set. On rootful engines the backend should pass an
  engine-side hook (A7). On rootless Podman the mapped uid of
  `HubProxyUID` depends on the userns mapping that P1-P measures. Pruning
  and `Create` can still remove proxy-owned files, because unlinking needs
  write permission on the host-owned directory, not ownership of the file.
- **Sticky status directory.** In a sticky directory the host user, as
  directory owner, can still delete root-owned or proxy-owned status files
  (`Create` does this on group reuse). Each hub reader can replace only its
  own file.
- **Directory fsync.** `EINVAL` and `ENOTSUP` from fsync on a directory are
  ignored (some filesystems and Windows).
- **Builds.** The package builds and vets for linux, darwin and windows
  (`make cross-build`, `make lint` runs the windows vet and gosec pass).
  `os.Symlink` for `current` needs privileges on Windows; A2A targets Linux
  and macOS hosts only, so this is not handled there.
- **No `config.HostA2A*` helpers.** Adding them made `internal/config`
  import `internal/peergroup`. That pulls `internal/peergroup` and
  `internal/a2a` into the gateway proxy build inputs, so
  `TestGatewayProxyBuildInputsCoverInternalDeps` fails and the gateway image
  hash would follow A2A code. The file that fixes that test is not A2's.
  The helpers are optional, so A2 leaves them out. Callers compose
  `peergroup.X(config.HostStateRootDir(home), ...)` and
  `NewGroupStore(config.HostStateRootDir(home), config.HostLocksDir(home))`.
  `host_paths.go` is unchanged. Accepted by the coordinator.

## Measured or chosen values

| Value | Choice | Why |
| --- | --- | --- |
| Status poll interval | 50 ms | Well below the 10 s ack timeout placeholder; reads are two small files |
| Lock poll | 10 ms doubling to 200 ms | Fast handoff without busy-waiting |
| Default lock timeout (no ctx deadline) | 2 min | Covers a join or leave that waits for acks (10 s) and departure acks (30 s) |
| Invocation credential lifetime | 1 s to 1 h; times truncated to seconds | Bounded; the published `expiresAt` equals the token's expiry. A12's option maximum must stay at or below `MaxInvocationLifetime` |
| Generation | 8 `crypto/rand` bytes, hex | interfaces.md conventions |

Test runtime: `go test -race -count=5 ./internal/peergroup` takes about 6 s,
0.95 s for one run.
