## Verbs and JSON kinds as shipped

| Verb | Flags | `--json` kind | Exit codes |
| --- | --- | --- | --- |
| `a2a peers` | `--peer-group`, `--json` | `a2a-peers` | 0, 1 |
| `a2a log` | `--peer-group`, `--tail <n>` | none (lines are JSON) | 0, 1 |
| `a2a send <peer> <text>` | `--peer-group`, `--detach`, `--context`, `--wait`, `--json`, `--backend` | `a2a-task` | 0, 1, 4, 5, 130 |
| `a2a task get <handle>` | `--peer-group`, `--wait`, `--json`, `--backend` | `a2a-task` | 0, 1, 4, 5, 130 |
| `a2a task cancel <handle>` | `--peer-group`, `--json`, `--backend` | `a2a-task` | 0, 1 |
| `a2a task retry <handle-or-message-id>` | `--peer-group`, `--wait`, `--json`, `--backend` | `a2a-task` | 0, 1, 4, 5, 130 |
| `a2a reconcile` | `--peer-group` (all groups without it), `--backend` | none | 0, 1, 3, 130 |

- `a2a-task`: `schemaVersion`, `kind`, `group` always; `peer`, `handle`,
  `state`, `queuePosition`, `messageId`, `context`, `reason`,
  `termination`, `message`, `error`, `note` when set. The task fields are
  A11's `Result` fields with the same names and meaning.
- `a2a-peers`: `schemaVersion`, `kind`, `group`, `groupGeneration`,
  `snapshotRevision`, `hub {container, port}`, `members[]` with `name`,
  `role`, `generation`, `state`, `tool`, `sessionContainer`, `projectPath`,
  `mountMode`, `description`, `port`, `hubAddress`, `joinedAt`, `skills`
  and the nine status fields of section 9.
- `ps --json`: every element gains `a2a` (`null` outside a group), shaped
  exactly as section 9. No envelope change (Q5).
- A `--json` error before any result is one object with `schemaVersion`,
  `kind` and `error`.

Behavior:

- `--peer-group` may be omitted when exactly one group has a record. A
  configured `peer_group` is used by every verb except `reconcile`, which
  covers all groups unless the flag is given on the command line.
- `send` and `task` issue a credential for the operation bound plus 60 s:
  `a2a_host_send_wait` (or `--wait`) for a blocking `send` or `retry`,
  `--wait` for `task get`, and 2 minutes for `--detach`, `cancel` and a
  `get` without `--wait`, all capped at `a2a_credential_lifetime`. A wait
  above the cap minus 60 s is a usage error (CR-P3-3). The credential is
  revoked in a deferred step that survives Ctrl-C.
- Blocking `send` posts `SendStreamingMessage`, follows the stream,
  resubscribes after a drop, uses `GetTask` on `-32004`, and resends
  unchanged on `-31019` before a task ID exists (CR-F1-3). When the wait
  elapses it prints the handle and state and exits 4. A `-31003` after the
  task ID (credential expired mid-stream) also exits 4 with the handle. A
  stream lost before the task ID is "outcome unknown", exit 1, with the
  message ID and a `task retry` hint.
- `--detach` posts `SendMessage` with `returnImmediately` and exits 0 once
  the worker admitted the task.
- Interrupting never cancels a task; the handle, if known, goes to stderr,
  exit 130.
- `peers` never contacts the hub. Card data (description, skills) comes
  from the committed `membership.json`, which is what the hub writes into
  every card anyway; queue depth is not shown.

## Group stop for I1

In `internal/app/a2a_cmd.go`:

```go
func runStopPeerGroup(opts model.Options, group string, stopSession func(ctx context.Context, container string) error) int
func stopPeerGroup(ctx context.Context, lc a2aLifecycle, store peergroup.GroupStore, group string, stopSession func(ctx context.Context, container string) error) (PeerGroupStopResult, error)
```

`command_stop.go` calls `runStopPeerGroup` and supplies `stopSession`, which
stops and removes one session container the way `stop <name>` does (auth
finalization, gateway). No prompt. The orchestrator leaves first while the
workers still run, so its departure is acknowledged; each member leaves
(`PeerGroups.Leave` with its generation) before its container is stopped, and
the last leave stops the hub and deletes the record. Exit codes: 0, 1 (a
leave or stop failed, the group does not exist), 3 (a leave was degraded;
the message points at `enclave a2a reconcile`), 130.

I1 also adds `peer_group` to the flags of `internal/cli/stop_command.go` and
dispatches on it. I did not add the flag: without the dispatch,
`stop --peer-group x` would fall through to the batch form, which removes
every background container of the tool.

## Change requests

- **CR-A13-1** (A7, `internal/backend/docker`): host invocation credentials
  have no API. `commitRevision` and the secrets owner are unexported, and an
  app-side publication cannot hand `secrets.json` to the proxy uid on
  rootful Docker. Proposed: `(*PeerGroups).IssueHostCredential(ctx, group
  string, lifetime time.Duration) (peergroup.InvocationCredential, error)`
  and `(*PeerGroups).RevokeHostCredential(ctx, group, hash string) error`,
  each one revision with purpose `credential` under the group lock.
  - Interim, in `a2a_host.go` (`engineA2AHostAccess.Issue`/`Revoke`): under
    the group lock, add or remove the hash and append a `snapshot-commit`
    obligation, then call `PeerGroups.Reconcile`, which republishes the
    record's membership with `CredentialHashes` and waits for both acks.
    The verb then checks that a newer revision committed with the expected
    credential set.
  - Costs of the interim: every host verb runs a full reconcile (it may
    finish leaves of gone members or retry departure acks, up to
    `a2a_departure_ack_timeout` per worker), and it fails as "busy" when
    another lifecycle holds the lock for more than 3 s.
- **CR-A13-2** (A7 or A6, backend): no exported way to exec in the hub with
  stdin. Proposed: `(*Backend).HubCall(ctx, ref backend.HubRef, path string,
  stdin io.Reader) (io.ReadCloser, error)` running `exec --interactive
  --user 65532 <hub> /usr/local/bin/enclave-a2a-hub call <path>`.
  - Interim: `engineA2AHostAccess.Call` runs the engine CLI named by the
    resolved backend (`docker` or `podman`, the binary
    `docker.SetBinary` selects) through `os/exec`. It does not import
    `internal/docker`, so the arch test passes, but it is engine access
    outside `internal/backend`.
- **CR-A13-3** (A7, `backend.Session`): sessions carry no labels, so `ps`
  cannot read `enclave.a2a.*`. Proposed: a `PeerGroup *SessionPeerGroup`
  (group, group generation, member, member generation, role) filled from
  the labels in `List`.
  - Interim: identity comes from the group records, matched by
    `sessionContainer`. A labeled session whose record is unreadable or
    gone gets `a2a: null` instead of the label fields with null record
    fields.
- **CR-A13-4** (section 3, host state): `task retry` must resend the
  original message ID, text and context. The adapter's content hash covers
  the text and `GetTask` returns no history. I keep a host send journal at
  `<state>/a2a/<group>/host-secrets/host-journal.json` (0600, at most 100
  entries, written under the group lock). It goes away with the
  `host-secrets/` directory on group deletion and group re-creation, so it
  is scoped to the group generation. Unlike A11's journal it stores the
  text, on the host only. Proposed: record the file in section 3.
- **CR-A13-5** (`AGENTS.md`, External Integrations): list
  `enclave a2a peers|send|task --json` (`a2a-peers`, `a2a-task`) and the
  `ps --json` `a2a` object as contracts. The file is not mine.

Deviations without a CR:

- `--wait <duration>` on `send`, `task get` and `task retry`. CR-P3-1 gives
  A13 the host flag, and A12 suggested it.
- `task retry` also accepts the message ID, because a send whose handle was
  lost has no handle.
- `--backend` on `send`, `task` and `reconcile`, like the other engine verbs.
- Timestamps where section 9 names no record: orchestrator `quarantine:
  no`, `departure: no` and orchestrator `admissionStop: no` without active
  workers use the member's `joinedAt`; orchestrator `admissionStop: no`
  from tables uses the oldest table heartbeat.
- `task get` on a running task without `--wait` exits 4, the code for a
  handle printed before the task ended. `cancel` exits 0 whenever the
  worker answered, whatever the termination.
