## Sequences as wired

**Run (`--peer-group`)**, in `runExecutionCommand`:

1. `ValidateOptions` (run actions): A2A option checks, before the qemu
   coercion so qemu gets its own message.
2. Profile loaded, yolo resolved: `validateA2AProfile`.
3. `newA2ARun`: `gateway.EnsureA2AHubImage` (honours `--no-rebuild`), hub
   env, bound session env, `Backend.PeerGroups`.
4. `runtime.SetPeerGroupJoiner`. Inside `Execute`/`ExecuteBackground`, after
   `prepareExecution` (which may have removed a stopped container of the
   same name) and under the interrupt context:
   `ReconcileAll` (problems logged, never fatal), then `PeerGroups.Join`,
   `Join.Warnings()` printed, orchestrators get `ENCLAVE_A2A_TABLE_DIR`
   appended to `join.Session().Env` (CR-A11-1), and the session goes into
   `backend.Request.PeerGroup`.
5. `be.Start` / `be.Run` complete the join (J6 to J12) or roll it back;
   a failed join fails the start with exit 1. A foreground session leaves on
   exit through A7's `LeaveOnExit`; `join.LeaveResult().Degraded` maps to
   exit 3 when the session itself exited 0.

**Run (plain session, docker or podman)**: when any group state exists
(`GroupStore.List` non-empty), one `ReconcileAll` before the session; with
no group state nothing A2A runs. The request is unchanged
(`TestPlainSessionBackendRequestUnchanged`).

**Stop**:

- `stop --peer-group <g>` (CLI source only): refused with a session
  argument or `--name`, then A13's `runStopPeerGroup` with a `stopSession`
  that stops (finalize) and removes like `stop <name>`, then `ReconcileAll`
  for the remaining groups. Never reaches the batch form. A configured
  `peer_group` does not trigger it.
- `stop <name>` and batch `stop`: members are ordered orchestrators first;
  each member `Leave`s (with its recorded generation) before its container
  is stopped and removed. After an orchestrator leaves, the remaining
  members and the `stop --peer-group` command are printed. Then
  `ReconcileAll`. A degraded leave or reconcile exits 3. Membership comes
  from the group records (`sessionContainer`), not labels.

**Cleanup `--ephemeral`** (not on dry run): exited gateways stopped, members
among the containers to remove leave (orchestrators first), containers
removed, `ReconcileAll` (before the network prune, so the hub is
disconnected from bridges of removed members), networks pruned, stores
removed. Degraded exits 3 with a hint.

All host-principal invocations stay in A13/F3 code; nothing in these files
execs into a hub or worker.

## Rejections

| Case | Message |
| --- | --- |
| `--role`/`--a2a-*` on the CLI without a group | `--role requires --peer-group` (flag name of the first such option) |
| qemu backend | `--peer-group requires --backend docker or podman; the qemu backend has no network gateway to isolate the group` |
| `--allow-all-network` (CLI or config) | `--peer-group is incompatible with --allow-all-network; the group route is part of the restricted network gateway` |
| no `--name` (or one that sanitizes to empty) | `--peer-group requires --name; the session name is the member name in the group` |
| `config.ValidateA2AOptions` | `invalid A2A options: <option>: <reason>` |
| worker, tool without `a2a` block | `tools.RequireA2A`: `tool "x" cannot run in serve mode: its spec.yaml has no sandbox.a2a block` |
| worker, tool without yolo flag | `--role worker needs yolo mode, and x has no yolo flag; nobody can approve permission prompts in serve mode` |
| worker, yolo off | `--role worker needs yolo mode, but it is disabled for this session; ... drop --no-yolo or yolo=false` |
| worker with `shell` | `--role worker runs the A2A adapter as the session's main process and cannot start a shell` |
| Podman without isolate | A7's join check at the session network (`--peer-group needs a podman session network with isolate=true or stronger ...`); not pre-checked, the network does not exist before start |
| `stop --peer-group` with a session or `--name` | `stop --peer-group stops every member of the group; drop ...` |

Configured `a2a_*` values without a group are accepted: every session
records the defaults, and a configured role or bound only matters once a
session joins. Only CLI sources are a usage error. An orchestrator whose
tool declares no `orchestratorArgs` gets a warning, not an error.

## Env

Identity and tokens come only from `PeerGroupSession.Env` (A7's env file).
I1 adds through `JoinSpec.SessionEnv`:

- both roles: `MAX_REQUEST_BYTES` (bytes via `ParseA2ASize`),
  `RECONNECT_WINDOW`;
- orchestrator: `SEND_WAIT`, plus `TABLE_DIR` after the join;
- worker: `QUEUE_DEPTH`, `TASK_DEADLINE`, `MAX_RESULT_BYTES`,
  `RECORD_LIMIT`, `RECORD_MAX_AGE`, `CONTEXT_TTL`, `TERMINATION_TIMEOUT`,
  `HARNESS` (the block plus `"yoloFlag"`, decoded in the test with the
  adapter's strict decoder). `ENCLAVE_YOLO=1` is the runtime's existing
  variable. `HEARTBEAT_INTERVAL` is not set (adapter constant).

Hub env (`PeerGroupConfig.HubEnv`): `LOG`, `HUB_RETAINED_RESULTS`,
`RECONNECT_WINDOW`, `MAX_REQUEST_BYTES`. Commit and departure ack timeouts
from the options. Durations are passed as Go `Duration.String()`.

## CR-A15-1 and CR-A15-2

- `sandbox.a2a.orchestratorArgs` is in `model.A2ASpec` (validated: no blank
  token, no `{sessionId}`), Claude's value is
  `[--mcp-config, /usr/local/share/enclave/templates/claude-a2a-mcp.json]`.
- Placement: unlike `noMemoryArgs` (before the user arguments), the
  orchestrator args go after the user arguments, and before a `--`
  terminator if there is one. Checked against Claude Code on this host:
  `claude -p --mcp-config X "hello"` reads `hello` as a second config file
  (`--mcp-config` is variadic); `claude -p "hello" --mcp-config X` and
  `claude -p --resume --mcp-config X` parse correctly. Tests cover a
  prompt, `--resume`, `--continue` with a prompt, `--` and no arguments,
  and that workers, shells and plain sessions get nothing.
- Extension and feature skills named `a2a-*` are composed only into
  sessions with a peer group, both in the skills mount and in the
  config-source layer. User shared skills are not filtered.

## Worker launch decision

Foreground by default, without a TTY: the adapter's log streams to the
terminal (one Herdr pane per worker, proposal 19), stdin is not attached,
and Ctrl-C reaches the adapter through the engine client's signal proxy
(`AttachIO{Out, Err}` with `TTY: false`, which the Docker backend runs as
`run` without `-i`/`-t`). `host_env` and the host `TERM` are not passed.
`--background` starts a worker detached as any other session (`-dit`),
and `enclave attach` shows its log. Orchestrators are unchanged
(interactive TTY).

## Open items for I2

- End to end on both engines: orchestrator `/mcp` lists `enclave-a2a`
  with four tools; a worker and a plain session list nothing new.
- Foreground worker without a TTY: Ctrl-C reaches the adapter and the
  leave runs (Docker and Podman signal proxying); the detach key does not
  apply.
- Latency: a plain session start or stop pays one `docker info` plus a
  reconcile per existing group, and a reconcile can wait up to
  `a2a_departure_ack_timeout` per unreachable worker. If that is too slow,
  the plain-session reconcile could be limited to groups with open
  obligations.
- `stop --peer-group` uses A13's lifecycle with the hub image tag only (no
  build); the image always exists once a group was joined.
- A restarted named member: the runtime removes the stopped container,
  then reconcile lets its old generation leave before the new join. A
  running container of the same name is still refused by the runtime
  before any A2A step.
- The orchestrator `TABLE_DIR` is appended to `PeerGroupSession.Env` after
  `Join`; if A7 later builds it in `buildSession`, drop the append.
