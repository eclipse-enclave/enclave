# P2 report: harness prototype

Date 2026-11-05. Host Linux 6.17, Claude Code 2.1.306, `--model haiku`
(`claude-haiku-5-5`), Docker and rootless Podman 4.9.3 for the init checks.
Branch `a2a-p2` from `33158d4`. Stand-ins and logs live in `/tmp/a2a-p2/`
(a Go executor stand-in `harness/main.go`, a strace wrapper, raw stream-json
logs). 12 billed Claude invocations, total cost under USD 0.02.

The stand-in starts `claude -p --output-format stream-json --verbose --model
haiku --setting-sources project,local` with `Setpgid`, the prompt on stdin,
`CLAUDE*` variables stripped, and `PR_SET_CHILD_SUBREAPER` set on itself. It
logs every event, cancels by signalling the process group, and polls `/proc`
for the descendant tree until it is empty.

## Failed: process-group kill does not reach tool processes

Proposal 9 says "the harness runs in its own process group; the adapter
confirms termination of every descendant". The first half is not enough:

- Claude's Bash tool starts every command in a new session
  (`pgid = sid = shell pid`), never in Claude's process group. Measured in
  every tool run: `claude pgid=X`, `zsh -c ... pgid=sid=Y`, children in `Y`,
  and `setsid` children in their own session `Z`.
- `kill(-pgid, SIGKILL)` removed Claude in 18 to 38 ms and left the whole
  tool tree running (shell, `sleep 300`, `sleep 302`, `setsid sleep 301`),
  reparented to the subreaper.
- `kill(-pgid, SIGTERM)` works only because Claude cooperates: it kills its
  tool trees itself (the tool result is `Exit code 137`) and the full tree,
  including the `setsid` child, was gone after 1.55 s in both timed runs. This
  depends on Claude being responsive; a hang, a crash or a SIGKILL leaves the
  tools alive.
- A natural, successful exit can also leave processes: a tool command
  `setsid nohup sleep 400 >/dev/null 2>&1 &` survived Claude's exit (twice).
  The adapter must sweep after success too, not only after cancel.

What works (verified): the adapter sets `PR_SET_CHILD_SUBREAPER`, so every
orphan, including `setsid` and double-forked ones, reparents to the adapter
and stays in its `/proc` ppid tree. Termination is "SIGTERM the harness
group, wait, then SIGKILL every pid in the adapter's descendant tree", and
confirmation is "descendant tree empty". Under `--init` the adapter is not
PID 1 (docker-init/catatonit is), so without the subreaper flag orphans go to
PID 1 and leave the adapter's tree. CR for A8: replace "process group" with
"subreaper descendant tree" in the executor's kill and `DescendantsAlive`
(the pgid is still useful as the first SIGTERM target and in `tasks/*.json`).

## Stream-json facts for the Claude driver (A9)

- Flags: `-p --output-format stream-json --verbose` (stream-json requires
  `--verbose`). Prompt on stdin works with no positional argument. No
  non-JSON lines appeared on stdout; errors outside the stream go to stderr.
- New context: `--session-id <uuid>` creates the session with that ID.
  Reusing an ID that has a transcript fails before any event: stderr
  `Error: Session ID <id> is already in use.`, exit 1, empty stdout.
- Resume: `--resume <id>` keeps the same session ID (no fork unless
  `--fork-session`). Unknown ID: no `system/init`; a single
  `{"type":"result","subtype":"error_during_execution","is_error":true,"errors":["No conversation found with session ID: <id>"]}`,
  exit 1. Resume looks the ID up across project directories, so cwd does not
  have to match, but the transcript stays in the directory of the cwd where
  the session was created.
- Every event carries `session_id`. The first event of a successful start is
  `{"type":"system","subtype":"init"}` with `session_id`, `cwd`, `model`,
  `tools`, `mcp_servers`, `permissionMode`, `claude_code_version`.
- The final message is the `result` field of `{"type":"result"}`, which also
  has `subtype` (`success`, `error_during_execution`), `is_error`,
  `terminal_reason` (`completed`), `stop_reason`, `num_turns`,
  `total_cost_usd`, `usage`, `permission_denials`. It equals the text of the
  last `assistant` event. Assistant events contain whole messages (text,
  tool_use, thinking blocks), not deltas, unless `--include-partial-messages`.
- **More than one `result` per process.** With background tasks enabled, a
  `run_in_background` Bash call kept the process alive after the first
  `result` (3.6 s); when the background task ended at 122 s Claude started a
  new turn by itself (`system/task_notification`, a second `system/init`, a
  second `assistant`, a second `result`) and only then exited. The final
  message is the last `result` before EOF, and the deadline covers the
  whole process. `CLAUDE_CODE_DISABLE_BACKGROUND_TASKS=1` removes the
  `run_in_background` parameter (the call fails validation) and the process
  exits after one `result`; A9 should set it. Whether it also stops
  background subagents and auto-backgrounding of long foreground commands is
  not verified (I2).
- **Killed runs have no `result`.** After SIGTERM the stream ended with the
  tool's `user`/`tool_result` (`Exit code 137`) and no `result`; while
  streaming, nothing was emitted after `system/init`. EOF without `result` is
  "no outcome", never success.
- Event types seen in 13 runs: `system` with subtypes `init`,
  `thinking_tokens`, `task_started`, `task_updated`, `task_notification`,
  `background_tasks_changed`, `permission_denied`; `assistant`; `user`;
  `rate_limit_event` (top-level, in almost every run); `result`. The
  interface comment "an unknown event is an error" (`Driver.Decode`) would
  fail on `rate_limit_event` and on any new `system` subtype unless the known
  set is complete for the pinned version. Suggested CR for A9: require
  `system/init` (or an error `result`) first and a `result` before EOF, and
  ignore or log other types and subtypes rather than failing the task.
- Bash tool commands run as `$SHELL -c "source <configDir>/shell-snapshots/snapshot-*.sh ... && <command>"`
  in their own session (see the failed item).

## Files Claude writes per session (for retention and inventory)

From strace of a tool-less turn and listings after tool runs, with
`<enc>` the creation cwd with `/` replaced by `-`:

- `<configDir>/projects/<enc>/<sessionId>.jsonl` (transcript: 39 KB after a
  one-line first turn, about 6 KB per further one-line turn)
- `<configDir>/projects/<enc>/memory/` (created even when unused)
- `<configDir>/session-env/<sessionId>/`, `<configDir>/sessions/<pid>.json`
  and key files, `<configDir>/shell-snapshots/`, `<configDir>/file-history/<sessionId>/`
  when edit tools run
- `$TMPDIR/claude-<uid>/<enc>/<sessionId>/tasks/*.output` (outside the
  config store)
- `~/.cache/claude-cli-nodejs/<enc>/` (MCP logs)
- `~/.claude.json` (via `~/.claude.json.lock`), `~/.local/state/claude/locks/`

None of these can be redirected into the table's reserved `transcripts/`
directory short of a separate `CLAUDE_CONFIG_DIR`, so `contexts.json`
`transcripts[]` must list the config-store-relative transcript, `session-env`
and `file-history` paths, and the `/tmp` task outputs disappear with the
container.
