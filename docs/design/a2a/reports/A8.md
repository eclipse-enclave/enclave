# A8 report: context table and executor

Branch `a2a-a8`, based on `33158d4` (tip of `a2a`).

## Summary

- `internal/a2aagent/contexttable`: `Table` implements `a2aagent.ContextTable`
  over the files of interfaces.md section 5, in a directory passed by the
  caller (no assumption about where it lives, see Q1). Every write is
  temp file, fsync, rename, directory fsync (`util.WriteFileAtomic`,
  `util.SyncDir`). The task file is the admission commit point: `Admit` writes
  the task file, then `dedupe.json`, then `contexts.json`, and rolls the task
  back if a later write fails. `Open` rebuilds a dedupe or context record that
  a crash left unwritten, rejects unknown `schemaVersion` values and files
  owned by another worker generation.
  Implemented: dedupe by (member, generation, message ID) with content binding
  and the ambiguous-retry rules, worker-issued 128-bit task and context IDs,
  principal and generation binding of tasks and contexts, tombstones with
  "expired" only for the binding's principal, persisted admission stops
  (never downgraded from authoritative) and quarantine (first one kept),
  heartbeat, idle TTL that never expires contexts with submitted or working
  tasks, transcript deletion on expiry (config-store-relative paths only),
  and count and age bounds for task records, dedupe records and tombstones
  that never evict active tasks.
- `internal/a2aagent/executor`: `Executor` implements `a2aagent.Executor`.
  One task at a time from `Table.Next`; each harness runs with `Setpgid`, its
  own stdin/stdout/stderr pipes (so `Wait` never blocks on a descendant that
  holds stdio), `ENCLAVE_A2A_*` removed from the environment, and the
  provenance line prepended to the prompt. Termination follows CR-P2-1 (see
  below). Unconfirmed termination persists the quarantine before the task's
  terminal record. Linux only: `proc_linux.go` holds `prctl`, `/proc` and
  signals; on other platforms `New` returns an error so the tree still
  compiles for darwin and windows.
- `internal/a2aagent/executor/fakedriver`: a reusable `a2aagent.Driver` whose
  harness is the test binary itself (`fakedriver.Main()` in `TestMain`), with
  modes for completion, failure, unknown events, hangs, SIGTERM-ignoring,
  same-group children, setsid children, double-forked grandchildren, and
  leftovers after success. A10 can use it for server tests.

## CR-P2-1 (accepted, from P2; implemented)

- The executor sets `PR_SET_CHILD_SUBREAPER` in `New`; failure to set it
  fails `New` (fail closed).
- Cancel, deadline, departure, epoch change, hub loss and adapter shutdown:
  SIGTERM to the recorded process group; after the termination timeout,
  SIGKILL to every pid in the executor's descendant tree (walked through
  `/proc/*/stat` ppid links, re-sent on every poll so late forks are caught);
  confirmed only when the tree is empty, else `unconfirmed` plus quarantine.
- After every run, success included, the tree is swept (SIGTERM to every
  leftover, SIGKILL after the timeout) and must be empty before the next
  dequeue.
- The pgid is still recorded in `tasks/*.json` and is the first SIGTERM
  target.
- `DescendantsAlive` is true when the subreaper tree is non-empty. It is also
  true while the quarantined pgid still has members: after an adapter restart
  the old harness is not in the new process's tree, so the pgid is the only
  handle left. This is stricter than the CR text; flagging it for review.
- Fixtures: setsid child and double-forked grandchild, on cancel and after
  success. The unkillable stand-in is an injected process lister that reports
  a phantom descendant (and, for the restart row, injected signal functions
  that drop signals), so no real process leaks.

## Change requests

All three decided by the coordinator on 2026-11-05. The coordinator updates
`agent.go` (the `Executor` interface gains `Submit` and `HubLost`, and the
`Depart` comment changes) and the `CtlRequest` comment in
`internal/a2a/enclave.go` on `a2a`.

- **CR-A8-1** (section 8, `Executor`), accepted: no method carried
  "reconnect window elapsed" (proposal 12 hub-lost). `HubLost(ctx) error`
  ends the running task (hub-lost, with termination) and fails queued tasks
  with hub-lost, not-applicable, because nothing observes them until the hub
  returns.
- **CR-A8-2** (sections 5 and 8), accepted: the message text had no path
  from the server to the executor, since `TaskRecord` holds only
  `contentHash`. `Submit(taskID, text string)` keeps the text in memory.
  Consequence: tasks still `submitted` when the adapter restarts are failed
  in `New` with outcome-unknown, not-applicable, since their text is gone.
  The executor builds the provenance line from `a2a.ProvenanceFormat`; A10
  must pass the bare message text.
- **CR-A8-3** (section 8 `Executor.Depart`, section 11 `CtlRequest`),
  accepted with a change: the single `Depart(ctx, principal, authoritative)`
  stays, and the separate `SuspectDeparture` was dropped.
  `authoritative=false` persists a `suspected` stop and discards the
  principal's queued tasks (orchestrator-lost, not-applicable). Running work
  continues to its deadline, and the ack has an empty `RunningTerminated` and
  `termination: not-applicable`. `authoritative=true` applies all three facts.

## Decisions inside the contract (accepted by the coordinator)

Cancel of a queued task (canceled, not-applicable) is an interpretation of
proposal 12; the coordinator documents it.

- A known message ID reused **without** the retry flag (same content) is
  refused with -31012 and reason `MESSAGE_ID_REUSED`, not admitted as a new
  task, since the dedupe key cannot hold two tasks.
- A flagged retry of a known original is answered before the quarantine and
  admission-stop checks: it returns the known outcome and starts nothing.
- `QueuePosition` counts the running task, so 0 means "starts now".
- Queue full means `submitted` count >= depth (the running task is excluded).
  A table whose record limit is filled by active tasks also answers -31016.
- Cancel of a queued task yields canceled, cancel, not-applicable. Proposal
  12 says canceled needs confirmed termination; a task that never ran has
  nothing to confirm. Change to `confirmed` if consumers test for it.
- A completed task carries `termination: confirmed` from the post-run sweep.
  If the sweep fails, the state follows the outcome, termination is
  unconfirmed, and the worker is quarantined.
- A harness failure (non-zero exit, unknown event, no final message) is
  failed with no reason and the sweep's termination.
- `Run` context end (adapter shutdown) kills the running task and records
  failed, outcome-unknown, with the measured termination.
- A `working` record with pgid 0 at restart (crash between persisting
  `working` and `Start`) is unconfirmed and quarantined: the process may
  exist and cannot be found.
- The departure ack carries `not-applicable` when nothing of the principal
  was running, and always for a suspected departure. The host's completion
  check must accept it next to `confirmed`.
- A missing context binding at start fails the task (proposal 14: resume is
  refused).
- The executor needs unbound lookups (`LookupTask`, `Tasks`) for `Cancel` and
  recovery, which the server has already authorized. It takes a local
  `executor.Table` interface (`a2aagent.ContextTable` plus those two), which
  `*contexttable.Table` satisfies. `a2aagent.ContextTable` is unchanged.
- Refusals are built as `*a2a.Error` directly (`contexttable.Refusal`),
  because `a2a.NewError` and `(*a2a.Error).Error` are still A1 stubs.

## Integration notes for A10

- Order: `contexttable.Open`, `executor.New`, then start `Run`, then serve.
  Call `Submit` right after a non-`Existing` `Admit`.
- The sweep kills every descendant of the adapter process, so the adapter
  must not keep other children alive while a task runs (for example, a
  `CheckVersion` run must not overlap a task).
- `Options.HeartbeatInterval > 0` makes `Run` call `Heartbeat` and `Expire`.
  Use it, or call both from the server, but not both.
- Calling `.Error()` or `%v` on a table refusal panics until A1 lands.

## Open items

- Q1 (same uid, writable table) is untouched. The table directory is a
  parameter.
- Pgid reuse: at restart, and in `DescendantsAlive`, a recorded pgid could
  name an unrelated new group. That fails closed (it is killed at restart or
  keeps the quarantine).
- After an adapter restart, descendants that left the old harness's group
  were reparented to init, not to the new adapter. Only the recorded pgid can
  be checked. P2 or I2 should confirm whether that is acceptable or whether
  the restart path needs a container-wide scan.
- Prompt text is not persisted (CR-A8-2), so queued work does not survive an
  adapter restart.
- Switch `contexttable.Refusal` to `a2a.NewError` once A1 merges.
